# 临床安全候选召回变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：临床安全候选召回、临床安全资产向量化、主业务对话入口中的安全信号生成、外部真实服务冒烟测试
>
> **不适用范围**：临床安全最终策略裁决、问诊状态机、RAG 医学知识问答、长期记忆写入策略、报告解析、管理后台资产治理完整实现

## 1. 变更目的

本次迁移将临床安全候选召回从静态 JSON 资产和文件短语回退路径中收束出来，改为以 PostgreSQL/pgvector 中已审核的临床安全 chunk 作为生产主召回路径。

迁移前，临床安全链路容易出现以下问题：

1. 文件资产、开发样例和生产数据边界不清。
2. 候选召回和关键词命中、动作裁决、短语兜底混在同一心智模型内。
3. 静态资产样式变化会影响生产安全行为，难以建立稳定 CI/CD 门禁。
4. 临床安全语义抽取失败时，硬编码关键词路径容易被误用为“语义事实”。
5. 后续接入 OPA 裁决时，难以区分“召回到了哪些风险候选”和“最终应采取什么动作”。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 结构化临床语义 | 语义提示事实 | 临床安全候选召回前 | 提供物种、时间、症状状态、暴露状态、意图等检索提示和裁决参考 |
| 临床安全 chunk | 可信资产候选 | PostgreSQL/pgvector | 保存已审核、已发布、可召回的临床安全资产片段 |
| 向量召回 | 可信候选来源 | 临床安全召回层 | 根据用户原文、可信宠物上下文和结构化语义 hints 召回候选资产 |
| 召回状态 | 可审计运行状态 | 响应 metadata | 表示是否使用 pgvector、命中数量、分数和降级原因 |
| 临床安全信号 | 候选归一结果 | 临床安全裁决前 | 表示可供后续策略裁决或安全响应使用的风险信号 |

临床安全候选召回只回答“有哪些已审核临床安全资产与本轮输入可能相关”。它不负责把用户文本解析成确定临床事实，也不负责决定最终是否急诊、阻断、降级或继续问诊。

## 2. 职责边界

### 2.1 候选召回层职责

候选召回层负责从生产可信资产中召回相关临床安全候选。

候选召回层当前负责：

1. 使用用户原文、可信宠物画像摘要和结构化临床语义 hints 构造召回查询。
2. 优先通过 PostgreSQL/pgvector 查询已启用、已审核、已发布的临床安全 chunk。
3. 返回候选分数、来源、chunk 类型、资产元数据和召回状态。
4. 在召回不可用或低命中时输出明确降级状态，而不是静默启用硬编码关键词事实。
5. 将召回摘要写入 `metadata.clinical_safety_resolution.fallback_state.retrieval`。

候选召回层不负责：

1. 从关键词直接生成临床事实。
2. 在 LLM 语义抽取失败时猜测暴露状态、否定状态、时间状态或症状是否正在发生。
3. 根据命中资产直接决定急诊、阻断、升级或继续问诊。
4. 维护临床安全响应模板。
5. 读取长期记忆或问诊状态作为主召回事实源。
6. 使用开发样例 JSON、静态 seed 资产或文件短语作为生产主路径。

### 2.2 临床安全资产数据职责

临床安全资产数据用于表达可召回的、经过审核的临床风险知识片段。

资产数据当前负责：

1. 保存稳定资产编码、资产类型、严重级别、适用范围和审计来源。
2. 保存可向量化的 chunk 文本、chunk 类型、embedding 模型和向量维度。
3. 支持按启用状态、审核状态、发布状态和向量相似度过滤候选。
4. 支持后续运营、医学审核和发布流程对资产形成稳定引用。

资产数据不负责：

1. 保存用户个体诊断结论。
2. 保存本轮模型语义抽取结果。
3. 作为问诊状态、RAG 知识库或长期记忆事实表的替代品。
4. 在数据库层实现策略动作或临床状态机。
5. 通过开发样例 JSON 作为生产可信源。

### 2.3 结构化语义结果职责

结构化临床语义结果用于辅助召回和后续裁决，但它不是召回层的回退规则状态机。

这里的“后续裁决”应理解为：由临床安全裁决域消费结构化语义结果，而不是让 `ClinicalSafetyEvaluator` 在 Python 业务层继续实现一套裁决状态机。`ClinicalSafetyEvaluator` 应逐步收缩为输入组装器或策略门面适配器，负责把候选、可信上下文、语义状态和降级信息整理成标准策略输入，不再承载最终动作判断。

结构化语义可以用于：

1. 扩展召回 query，提高同义表达、时间语义和高风险短语的命中概率。
2. 辅助判断资产适用范围，例如物种、时间状态、暴露状态和否定状态。
3. 在响应 metadata 中提供可审计的语义状态。
4. 在低置信或失败时触发明确降级标记。
5. 为后续裁决域提供可追溯的语义上下文，而不是替代裁决域输出最终动作。

结构化语义不用于：

1. 代替 pgvector 候选召回。
2. 在低置信或失败时启用硬编码关键词路径生成语义事实。
3. 直接写入长期记忆事实。
4. 直接生成最终医疗建议。
5. 作为 OPA 以外的动作策略来源。
6. 直接决定严重级别、时间裁决、毒物特例或是否急诊。

### 2.4 后续临床安全裁决职责

本次迁移保留现有临床安全裁决接口和外部响应语义，为后续 OPA 策略迁移留下清晰输入边界。

本节描述的是最终裁决域的职责，而不是 `ClinicalSafetyEvaluator` 的职责上限。过渡期内，`ClinicalSafetyEvaluator` 只应完成候选与上下文的标准化组装，不应继续扩展为自定义规则状态机。

后续裁决层应消费：

1. 向量召回候选。
2. 候选分数、来源、chunk 类型和资产元数据。
3. 结构化临床语义结果。
4. 可信宠物画像摘要。
5. 召回状态、语义状态和降级原因。
6. 本轮身份与会话边界摘要。

后续裁决层不应要求候选召回层提前输出最终动作。是否急诊、是否只提示 caution、是否因为语义低置信而降级、是否继续问诊，应由临床安全裁决层或后续 OPA 策略门面统一决定。

在代码迁移上，这意味着 `ClinicalSafetyEvaluator` 中的 `_intent_applies()`、`_effective_severity()`、`_toxic_severity()`、`_temporal_applies()`、`_adjust_temporal_severity()` 等规则裁决逻辑应被持续下沉或移出，最终仅保留输入装配、候选归一和策略门面适配职责。

## 3. 接口兼容边界

### 3.1 已覆盖的主业务入口

以下入口继续使用既有请求和响应结构，无需调用方新增字段：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已覆盖 | 主业务对话入口，临床安全候选召回位于输入安全放行和宠物上下文加载之后 |
| `POST /openai/v1/responses` | 已覆盖 | OpenAI Responses 风格兼容入口，与主业务入口使用同一临床安全召回语义 |

临床安全候选召回不改变入口请求字段。调用方仍通过既有 `input`、`scope_assertion`、`vet_context`、`attachments`、`metadata` 和 `turn_options` 提交请求。

### 3.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次候选召回迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 继续作为用户原文来源；召回层可使用原文构造 query，但不得从原文关键词直接生成临床事实 |
| `scope_assertion.profile` | 继续作为可信宠物画像来源；可进入召回和裁决上下文 |
| `vet_context.pet_info` | 继续作为未验证资料兼容字段；不得覆盖可信画像参与临床硬判断 |
| `metadata` | 继续作为审计透传字段；不得作为临床候选硬规则源 |
| `model` | 继续影响模型调用选择，不改变召回接口契约 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |

后续如果需要显式传入结构化临床上下文，应通过独立接口契约评审，不应复用 `metadata` 或未验证 `vet_context.pet_info` 作为隐式权威来源。

### 3.3 稳定的响应可观察字段

临床安全候选召回通过响应 metadata 和安全信号对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.clinical_safety_resolution` | 本轮临床安全召回与裁决摘要 |
| `metadata.clinical_safety_resolution.fallback_state.retrieval` | 召回阶段状态，包含阶段、来源、命中数量、降级原因等 |
| `metadata.clinical_safety_semantic` | 结构化临床安全语义结果摘要 |
| `safety_signals` | 可包含由召回候选和语义结果归一后的临床安全信号 |
| `status=safety_escalated` | 临床安全链路认为需要安全升级响应 |
| `segments[].type=safety` | 表示响应来自临床安全或安全升级链路 |

后续模块应依赖这些稳定字段进行跨领域对齐，不应依赖内部类名、SQL 语句、召回实现细节或测试数据前缀。

### 3.4 暂未纳入本次迁移的接口

以下接口或领域不以本文档作为临床安全候选召回契约来源：

| 模块 | 当前状态 | 保留原因 |
|---|---|---|
| 管理后台资产治理 | 暂未完整实现 | 医学资产新增、审核、发布、回滚和审计需要单独接口与权限模型 |
| 报告解析 | 暂未纳入 | 报告解析属于独立输入域，影像、化验和报告结果需要单独安全边界 |
| RAG 知识问答 | 保留独立链路 | RAG 面向知识证据回答，不替代临床安全候选召回 |
| 长期记忆写入 | 保留独立链路 | 记忆事实不是临床安全候选资产来源 |
| 输出安全复核 | 保留独立链路 | 输出安全约束不等同于输入侧临床安全候选召回 |

这些保留路径不是临床安全候选召回失败时的隐式回退机制。

## 4. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收用户原文、可信范围声明、未验证宠物资料审计副本和幂等键 |
| 范围授权与 turn lock | 确定可信用户、宠物、会话范围，并进入统一回合执行边界 |
| 基础输入安全 | 先裁决输入完整性、附件能力边界和提示注入等非临床输入风险 |
| 宠物上下文加载 | 只加载服务端可信宠物画像，不用请求侧 pet_info 覆盖 |
| 临床安全语义抽取 | 输出结构化语义或明确低置信、失败状态 |
| 临床安全候选召回 | 使用 pgvector 从已审核临床安全 chunk 中召回候选 |
| 临床安全信号归一 | 将候选、语义和可信宠物上下文组装为可审计信号 |
| 主链路分支 | 如触发安全升级则生成安全响应；否则继续问诊、RAG、回复生成和记忆写入 |
| 响应审计 | 写入召回状态、语义状态、候选来源、安全信号和降级原因 |

后续领域模块应把临床安全候选召回视为“临床安全裁决前的候选资产检索边界”，不是最终临床策略、问诊状态机或医学 RAG 引擎。

## 5. 召回语义

临床安全候选召回的准确定位是：

```text
基于本轮输入和可信上下文，从已审核临床安全资产中召回可能相关的候选片段
```

召回结果可以用于：

1. 提供临床安全风险候选。
2. 提供候选来源、分数、资产编码和审计元数据。
3. 辅助临床安全裁决层判断是否需要安全信号。
4. 在 metadata 中暴露召回质量和降级状态。
5. 支持外部真实服务冒烟测试验证 pgvector 主路径。

召回结果不得用于：

1. 直接证明用户当前陈述一定成立。
2. 直接替代 LLM 结构化语义结果。
3. 直接决定急诊、阻断、用药、剂量或治疗建议。
4. 直接写入长期记忆事实。
5. 绕过 OPA 或后续策略门面形成最终动作。

## 6. 降级与 Fail Fast 规则

临床安全候选召回需要区分“候选召回低质量”和“语义事实不可用”。

允许的降级：

1. 结构化语义低置信时，仍可使用用户原文和可信宠物上下文进行向量召回。
2. pgvector 命中不足时，可返回明确的低命中召回状态。
3. embedding 服务不可用时，可返回明确的召回降级状态。
4. 候选分数不足时，可保留审计信息但不形成强安全信号。
5. 开发或测试环境可显式注入替身仓储，但必须保持相同外部契约。

不允许的降级：

1. 不允许在语义抽取失败时通过关键词猜测暴露状态、否定状态、时间状态或症状状态。
2. 不允许在 pgvector 不可用时静默启用文件短语作为生产主路径。
3. 不允许把开发样例 JSON、seed 文件或静态资产作为生产可信召回源。
4. 不允许 OPA 或策略层直接扫描原始用户文本生成候选。
5. 不允许召回层在依赖不可用时伪造候选或伪造安全信号。

Fail Fast 的含义不是完全停止回答，而是不能把不可信的规则猜测包装成可信语义事实。系统可以继续尝试低置信原文召回，但必须在 metadata 中暴露召回状态和降级原因。

## 7. 配置与运行边界

当前临床安全候选召回相关配置保持有限集合：

| 配置 | 当前语义 | 边界说明 |
|---|---|---|
| `DATABASE_URL` | PostgreSQL 连接地址 | 生产临床安全候选召回依赖 PostgreSQL/pgvector |
| `LITELLM_BASE_URL` | LiteLLM OpenAI 兼容接口地址 | 用于结构化语义抽取和 embedding |
| `LITELLM_API_KEY` | LiteLLM API 密钥 | 由环境变量或 GitHub Environment 注入 |
| `QWEN_MODEL` | 默认文本模型 | 用于临床安全语义抽取 |
| `QWEN_EMBEDDING_MODEL` | embedding 模型 | 需要与已写入 chunk 的向量维度和模型记录一致 |
| `ENABLE_RAG_EMBEDDINGS` | 是否启用通用 RAG embedding | 不等同于关闭临床安全候选召回的生产要求 |
| `CLINICAL_SAFETY_VECTOR_MIN_SCORE` | 临床安全向量召回最低分数 | 只影响候选召回门槛，不代表最终安全动作阈值 |
| `ENABLE_LLM_SEMANTIC_EXTRACTION` | 是否启用 LLM 语义抽取 | 关闭时应明确产生语义降级状态，不启用关键词事实兜底 |

敏感参数应通过 env 注入；服务配置、编排和发布版本应继续遵守 Docker、GitHub Release 与 CI/CD 文档中的约束。

| 召回质量评估集 | 当前以单元测试和真实服务冒烟覆盖核心路径 | 后续建立医学审核样本集、误召回/漏召回指标和回归门禁 |
| 低置信语义策略 | 当前低置信语义只作为降级状态和裁决参考 | 后续由 OPA 决定低置信时是否仅 caution、是否继续追问、是否要求线下就医提示 |
| 多语言与同义词治理 | 当前依赖 embedding 和资产文本覆盖 | 后续通过资产治理或结构化语义模型扩展，不在召回层新增硬关键词状态机 |
| 文件仓储定位 | 当前文件仓储不得作为生产主路径 | 后续如保留，应限定为开发演示、离线导入源或应急人工排障，不进入默认生产召回 |

## 9. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不把临床安全候选召回改造成最终临床策略引擎。
2. 不把关键词、正则或短语匹配作为生产主召回路径。
3. 不在语义抽取失败时通过硬编码规则猜测用户真实临床状态。
4. 不把临床安全资产表作为 RAG 知识库、问诊状态或长期记忆事实表。
5. 不让 OPA 扫描原始用户文本生成候选。
6. 不让开发样例 JSON、seed 文件或静态资产决定生产安全行为。
7. 不在召回层生成药物剂量、治疗方案或诊断结论。
8. 不让未验证 `vet_context.pet_info` 覆盖服务端可信宠物画像。
9. 不隐藏 embedding、pgvector、语义抽取等依赖失败。

## 10. 后续实现对齐原则

后续迁移临床安全裁决、RAG、记忆、报告和策略治理时，应遵循以下约束：

1. 临床安全候选召回只输出候选和召回状态，不输出最终动作。
2. 临床安全最终动作应由独立裁决层或 OPA 策略门面统一产生。
3. 新增候选来源时，应先定义来源可信等级、候选编码、置信度、审计字段和降级语义。
4. 新增资产类型时，应同步定义适用范围、chunk 类型、审核状态和召回质量验证方式。
5. 调整阈值时，应区分召回阈值、信号阈值和策略动作阈值。
6. 低置信语义可以降低动作激进程度，但不得触发关键词事实兜底。
7. RAG 医学知识召回不得替代临床安全候选召回。
8. Mem0 语义记忆不得作为临床安全候选的唯一依据。
9. 输出安全、报告解析和管理接口应各自定义安全边界，不复用临床安全候选召回作为泛化规则工具。
10. `ClinicalSafetyEvaluator` 应被视为过渡期输入适配层，不应再次演化为裁决状态机。

## 11. 验收基线

当前阶段后续修改不应破坏以下基线：

1. 临床安全候选生产主路径使用 PostgreSQL/pgvector。
2. 候选召回只返回已启用、已审核、带向量的临床安全 chunk。
3. 结构化语义失败或低置信时，不启用硬编码关键词事实兜底。
4. pgvector 召回状态、命中数量和来源可在 metadata 中观察。
5. 临床安全候选和基础输入安全候选保持边界独立。
6. 未验证 `vet_context.pet_info` 不覆盖可信宠物画像。
7. 开发样例 JSON 和静态 seed 资产不作为 CI 静态检查或生产安全行为可信源。
8. 外部真实服务冒烟测试可以验证 LiteLLM、OPA、PostgreSQL/pgvector 和 Mem0 可达性及核心 API 路径。
9. 默认快速 CI 不要求真实外部服务，真实冒烟测试需显式开启。
