# 临床安全语义抽取变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：临床安全语义抽取、结构化语义结果、候选召回增强、裁决前策略输入、响应 metadata 审计
>
> **不适用范围**：临床安全候选召回实现、临床安全最终策略裁决、医学 RAG 知识问答、问诊状态机、长期记忆写入、报告解析和管理后台资产治理

## 1. 变更目的

本次迁移将临床安全语义抽取从手写 JSON 解析、Markdown code fence 兼容解析和关键词规则回退路径中收束出来，改为以 LiteLLM `response_format` 和 Pydantic 契约作为结构化语义主路径。

迁移前，临床安全语义链路容易出现以下问题：

1. 模型输出只依赖提示词要求“只输出 JSON”，业务代码仍需要进行字符串解析和宽松修复。
2. LLM 失败或低置信时，硬编码关键词规则会补造物种、暴露、症状、时间、否定等语义事实。
3. 结构化语义、候选召回和动作裁决容易被理解为同一套规则状态机。
4. 下游 evaluator 可能把规则猜测结果误认为可信语义抽取结果。
5. 后续迁移 OPA 裁决时，难以区分“本轮语义是否可信”和“最终动作是否应升级或降级”。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 用户本轮输入 | 原始陈述 | 入口请求 | 作为语义抽取和候选召回的输入文本 |
| 可信宠物画像摘要 | 服务端可信上下文 | 宠物上下文加载之后 | 辅助结构化语义抽取和候选召回增强 |
| 结构化临床语义 | 可信语义提示事实 | 临床安全语义抽取层 | 提供物种、暴露、症状、时间、否定、意图等结构化结果 |
| 语义可信状态 | 可审计运行状态 | 响应 metadata | 表示本轮语义是否可信、低置信、禁用、不可用、失败或 schema 非法 |
| 召回增强 hints | 派生检索提示 | 临床安全候选召回前 | 仅在语义可信时增强 pgvector 召回 query |

临床安全语义抽取只回答“用户本轮输入和可信宠物画像中可被结构化表达的临床安全语义是什么”。它不负责召回临床安全资产，不负责生成最终安全信号，也不负责决定是否急诊、阻断、降级或继续问诊。

## 2. 职责边界

### 2.1 语义抽取层职责

语义抽取层负责把用户本轮输入和可信宠物上下文转换为稳定结构化语义。

语义抽取层当前负责：

1. 使用 LiteLLM `response_format` 执行结构化模型输出约束。
2. 使用 Pydantic 契约校验结构化字段、枚举边界、置信度范围和审计短语集合。
3. 输出结构化临床语义、置信度、策略状态、失败原因和来源文本摘要。
4. 在低置信、禁用、不可用、调用失败或 schema 非法时返回明确降级状态。
5. 仅在结构化语义可信时提供召回增强 hints。
6. 将语义摘要写入 `metadata.clinical_safety_semantic`。

语义抽取层不负责：

1. 从关键词、正则或短语规则中补造临床语义事实。
2. 在 LLM 失败时猜测暴露状态、否定状态、时间状态、症状状态、物种或性别。
3. 召回临床安全资产或生成候选。
4. 直接生成安全信号、严重级别、急诊提示或阻断动作。
5. 读取长期记忆、RAG 知识库或开发样例作为语义权威来源。
6. 生成诊断、治疗方案、药物剂量或处置建议。

### 2.2 结构化语义结果职责

结构化临床语义结果用于表达本轮输入中的临床安全语义提示事实。

结构化语义可以表达：

1. 物种、性别、年龄阶段和年龄原文。
2. 暴露状态、症状状态、时间状态、时间范围和事件恢复状态。
3. 用户意图类型。
4. 用户原文中明确出现的高风险线索和被明确否定的线索。
5. 结构化抽取置信度、策略状态、失败原因和来源文本摘要。

结构化语义不表达：

1. 用户个体诊断结论。
2. 临床安全资产命中结果。
3. 最终安全动作或最终严重级别。
4. 长期记忆可写事实。
5. 医学知识证据引用。
6. 宠物画像的权威持久化结果。

### 2.3 可信状态职责

语义可信状态用于区分“可作为结构化输入使用”和“只能作为降级审计状态观察”。

当前稳定状态包括：

| 状态 | 语义 | 允许用途 |
|---|---|---|
| `llm` | LiteLLM 结构化输出通过 Pydantic 校验且达到置信度阈值 | 可进入召回增强和后续策略输入 |
| `llm_low_confidence` | 结构化输出通过校验但低于置信度阈值 | 只进入 metadata 和降级状态，不参与召回增强或激进裁决 |
| `disabled` | 当前环境显式关闭 LLM 语义抽取 | 只进入 metadata 和降级状态 |
| `unavailable` | 模型客户端或 LiteLLM 不可用 | 只进入 metadata 和降级状态 |
| `failed` | 模型调用或结构化调用失败 | 只进入 metadata 和降级状态 |
| `invalid_schema` | 模型返回不符合结构化契约 | 只进入 metadata 和降级状态 |
| `skipped` | 本轮未请求语义抽取或未传入结果 | 只作为默认未执行状态 |

可信状态不应被理解为最终策略动作。`llm` 只表示结构化语义可以作为输入使用，不表示必须急诊；`llm_low_confidence` 只表示语义不可作为可信事实使用，不表示可以忽略临床安全候选。

### 2.4 与候选召回的边界

临床安全语义抽取位于候选召回之前，但它不是候选召回本身。

语义抽取对候选召回的影响仅限于：

1. 在可信时提供 query hints，提高同义表达、时间语义和风险线索召回质量。
2. 在不可信时返回空 hints，避免低置信或失败语义污染 pgvector 查询。
3. 在 metadata 中暴露语义降级原因，便于解释召回质量和后续裁决输入。

候选召回仍应以 PostgreSQL/pgvector 中已审核、已发布的临床安全 chunk 作为生产主路径。语义抽取失败时，系统可以继续使用用户原文和可信宠物画像进行向量召回，但不得把关键词猜测出的语义字段传入后续链路。

### 2.5 与临床安全裁决的边界

临床安全语义抽取只提供结构化输入，不输出最终动作。

后续临床安全裁决域可以消费：

1. 可信结构化语义结果。
2. 低置信、失败或不可用的语义状态。
3. 候选召回结果、分数、来源和资产元数据。
4. 可信宠物画像摘要。
5. 本轮身份、宠物和会话边界摘要。

后续裁决域不应要求语义抽取层提前输出 urgent、caution、suppress、block、followup 等动作。是否生成安全信号、是否急诊、是否因为语义低置信而降级、是否继续追问，应由临床安全裁决层或后续 OPA 策略门面统一决定。

## 3. 接口兼容边界

### 3.1 已覆盖的主业务入口

以下入口继续使用既有请求和响应结构，无需调用方新增字段：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已覆盖 | 主业务对话入口，临床安全语义抽取位于宠物上下文加载之后、候选召回之前 |
| `POST /openai/v1/responses` | 已覆盖 | OpenAI Responses 风格兼容入口，与主业务入口使用同一临床安全语义抽取语义 |

临床安全语义抽取不改变入口请求字段。调用方仍通过既有 `input`、`scope_assertion`、`vet_context`、`attachments`、`metadata` 和 `turn_options` 提交请求。

### 3.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次语义抽取迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 继续作为用户本轮原文来源；可进入结构化语义抽取和原文向量召回 |
| `scope_assertion.profile` | 继续作为服务端可信宠物画像来源；可进入语义抽取上下文 |
| `vet_context.pet_info` | 继续作为未验证资料兼容字段；不得覆盖服务端可信画像形成权威语义事实 |
| `metadata` | 继续作为审计透传字段；不得作为临床语义硬规则来源 |
| `model` | 继续影响模型调用选择，不改变语义抽取接口契约 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |

后续如果需要调用方显式传入结构化临床语义，应通过独立接口契约评审，不应复用 `metadata` 或未验证 `vet_context.pet_info` 作为隐式权威来源。

### 3.3 稳定的响应可观察字段

临床安全语义抽取通过响应 metadata 对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.clinical_safety_semantic` | 本轮临床安全结构化语义摘要 |
| `metadata.clinical_safety_semantic.strategy` | 结构化语义策略或失败状态 |
| `metadata.clinical_safety_semantic.confidence` | 结构化语义整体置信度 |
| `metadata.clinical_safety_semantic.fallback_reason` | 语义低置信、失败、禁用或不可用原因 |
| `metadata.clinical_safety_semantic.fallback_state` | 结构化语义层显式降级状态 |
| `metadata.clinical_safety_resolution.fallback_state.semantic` | 临床安全结果中透出的语义状态摘要 |
| `metadata.clinical_safety_resolution.fallback_state.retrieval` | 候选召回状态；用于与语义状态共同解释临床安全链路 |

后续模块应依赖这些稳定字段进行跨领域对齐，不应依赖内部类名、提示词内容、模型原始响应、测试替身或调用栈细节。

### 3.4 暂未纳入本次迁移的接口

以下接口或领域不以本文档作为结构化语义契约来源：

| 模块 | 当前状态 | 保留原因 |
|---|---|---|
| 临床安全最终裁决 | 待迁移 | 最终动作应由独立裁决层或 OPA 策略门面统一输出 |
| 问诊语义抽取 | 独立阶段 | 问诊语义进入问诊状态，不等同于临床安全语义 |
| 管理后台资产治理 | 暂未完整实现 | 医学资产审核、发布和回滚需要单独接口与权限模型 |
| RAG 知识问答 | 保留独立链路 | RAG 面向知识证据回答，不替代临床安全语义抽取 |
| 长期记忆写入 | 保留独立链路 | 记忆事实候选需单独抽取和策略裁决 |
| 报告解析 | 暂未纳入 | 影像、化验和报告结果需要独立结构化边界 |

这些保留路径不是临床安全语义抽取失败时的隐式回退机制。

## 4. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收用户原文、可信范围声明、未验证宠物资料审计副本和幂等键 |
| 范围授权与 turn lock | 确定可信用户、宠物、会话范围，并进入统一回合执行边界 |
| 基础输入安全 | 先裁决输入完整性、附件能力边界和提示注入等非临床输入风险 |
| 宠物上下文加载 | 只加载服务端可信宠物画像，不用请求侧 pet_info 覆盖 |
| 临床安全语义抽取 | 使用结构化模型输出生成可信语义或显式降级状态 |
| 临床安全候选召回 | 使用用户原文、可信上下文和可信语义 hints 从 pgvector 召回候选 |
| 临床安全信号归一 | 将候选、语义状态和可信上下文组装为可审计信号或策略输入 |
| 主链路分支 | 如触发安全升级则生成安全响应；否则继续问诊、RAG、回复生成和记忆写入 |
| 响应审计 | 写入语义状态、召回状态、候选来源、安全信号和降级原因 |

后续领域模块应把临床安全语义抽取视为“临床安全候选召回前的可信语义结构化边界”，不是候选召回器、最终裁决器、问诊状态机或医学 RAG 引擎。

## 5. 语义抽取语义

临床安全语义抽取的准确定位是：

```text
基于用户本轮输入和服务端可信宠物画像，生成可审计的结构化临床安全语义或显式失败状态
```

语义结果可以用于：

1. 提供召回增强 hints。
2. 提供后续裁决域可消费的结构化语义输入。
3. 提供语义置信度、失败原因和来源文本摘要。
4. 在 metadata 中暴露语义质量和降级状态。
5. 支持真实服务冒烟测试验证 LiteLLM `response_format` 与 Pydantic 契约。

语义结果不得用于：

1. 直接证明用户当前陈述一定成立。
2. 直接替代 pgvector 候选召回。
3. 直接决定急诊、阻断、用药、剂量或治疗建议。
4. 直接写入长期记忆事实。
5. 绕过 OPA 或后续策略门面形成最终动作。
6. 作为关键词、正则或短语状态机的包装层。

## 6. 降级与 Fail Fast 规则

临床安全语义抽取需要区分“无可信语义”和“临床安全链路完全不可用”。

允许的降级：

1. LLM 语义抽取禁用时，返回明确的 `disabled` 状态。
2. LLM 或 LiteLLM 不可用时，返回明确的 `unavailable` 状态。
3. LLM 调用失败时，返回明确的 `failed` 状态。
4. 结构化响应不符合契约时，返回明确的 `invalid_schema` 状态。
5. 结构化响应低于置信度阈值时，返回明确的 `llm_low_confidence` 状态。
6. 无可信语义时，仍可使用用户原文和可信宠物上下文进行向量召回。

不允许的降级：

1. 不允许在语义抽取失败时通过关键词补造暴露状态、否定状态、时间状态或症状状态。
2. 不允许在低置信时用规则结果替换结构化字段。
3. 不允许在 schema 非法时宽松修复字段后继续作为可信语义。
4. 不允许使用 Markdown code fence、正则截取或字符串扫描作为结构化输出主路径。
5. 不允许把开发样例 JSON、seed 文件或静态资产作为语义抽取失败后的事实来源。
6. 不允许让 OPA 或策略层扫描原始文本来补造语义事实。

Fail Fast 的含义不是整个 Agent 立即停止回答，而是该阶段不能产出可信结构化语义时，必须显式暴露失败或降级状态，并禁止伪造语义事实。系统可以继续做低置信原文向量召回，但后续链路必须知道“本轮无可信结构化语义”。

## 7. 配置与运行边界

当前临床安全语义抽取相关配置保持有限集合：

| 配置 | 当前语义 | 边界说明 |
|---|---|---|
| `LITELLM_BASE_URL` | LiteLLM OpenAI 兼容接口地址 | 用于结构化语义抽取模型调用 |
| `LITELLM_API_KEY` | LiteLLM API 密钥 | 由环境变量或 GitHub Environment 注入 |
| `QWEN_MODEL` | 默认文本模型 | 用于临床安全语义抽取 |
| `QWEN_FALLBACK_MODELS` | 文本模型候选回退列表 | 仅影响模型调用候选，不改变语义契约 |
| `QWEN_MAX_RETRIES` | 模型调用重试次数 | 重试耗尽后应进入显式失败状态 |
| `ENABLE_LLM_SEMANTIC_EXTRACTION` | 是否启用 LLM 语义抽取 | 关闭时应产生显式禁用状态，不启用关键词兜底 |
| `SEMANTIC_EXTRACTION_MIN_CONFIDENCE` | 语义抽取最低可信置信度 | 只影响语义可信门槛，不代表最终安全动作阈值 |

敏感参数应通过 env 注入；服务配置、编排和发布版本应继续遵守 Docker、GitHub Release 与 CI/CD 文档中的约束。

| TODO | 边界说明 | 后续建议 |
|---|---|---|
| 临床安全 OPA 裁决 | 语义抽取已收束为结构化输入，但最终动作仍未完全迁移为 OPA 策略门面 | 后续将候选、语义、可信画像和降级状态组装为策略输入，由 OPA 输出动作 |
| ClinicalSafetyEvaluator 职责收缩 | 过渡期 evaluator 仍可能保留候选归一和少量兼容裁决逻辑 | 后续仅保留输入组装、候选归一和策略门面适配，不再承载动作规则 |
| 语义抽取质量评估集 | 当前以单元测试和真实服务冒烟覆盖核心契约 | 后续建立医学审核样本集、低置信样本、schema 回归样本和多语言表达样本 |
| response_format 能力治理 | 当前依赖 LiteLLM 结构化输出能力 | 后续跟踪模型与 LiteLLM 对 JSON Schema 支持差异，建立兼容矩阵和降级门禁 |
| 临床语义字段版本治理 | 当前字段集合满足临床安全候选召回和裁决前输入 | 后续新增字段需同步定义可信语义、降级语义、metadata 兼容策略和策略输入映射 |
| 问诊语义抽取迁移对齐 | 临床安全语义与问诊语义属于不同阶段 | 后续问诊语义抽取迁移时复用结构化输出原则，但不得共享临床安全动作语义 |
| 真实服务冒烟覆盖 | 当前可通过显式外部测试验证核心服务可达 | 后续补充 schema 非法、低置信、模型不可用和超时场景的真实服务或契约测试 |

## 9. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不把临床安全语义抽取改造成最终临床策略引擎。
2. 不把关键词、正则或短语匹配作为语义事实回退路径。
3. 不在语义抽取失败时生成任何猜测型结构化语义。
4. 不让未验证 `vet_context.pet_info` 覆盖服务端可信宠物画像。
5. 不把结构化语义结果直接写入长期记忆事实。
6. 不把临床安全语义抽取结果作为 RAG 知识证据。
7. 不让 OPA 或策略层扫描原始文本补造语义事实。
8. 不把低置信语义作为升级或降级的事实依据。
9. 不隐藏 LiteLLM、response_format、Pydantic 校验等依赖失败。

## 10. 后续实现对齐原则

后续迁移临床安全候选召回、临床安全裁决、RAG、记忆、报告和策略治理时，应遵循以下约束：

1. 临床安全语义抽取只输出结构化语义或显式失败状态，不输出最终动作。
2. 可信语义只来自 LiteLLM `response_format` 与 Pydantic 校验后的结果。
3. 低置信、禁用、不可用、失败和 schema 非法状态不得补造语义字段。
4. 语义抽取失败不阻断向量召回，但向量召回不得接收伪造语义 hints。
5. 临床安全候选召回只使用 pgvector 资产候选，不从语义结果生成候选。
6. 临床安全最终动作应由独立裁决层或 OPA 策略门面统一产生。
7. `ClinicalSafetyEvaluator` 应被视为过渡期输入适配层，不应再次演化为裁决状态机。
8. 调整置信度阈值时，应区分语义可信阈值、召回阈值、信号阈值和策略动作阈值。
9. 新增语义字段时，应同步定义字段来源、未知值、低置信处理、metadata 兼容和策略输入映射。
10. 测试文件应按职责分层，语义抽取测试不得断言 urgent、caution、suppress、downgrade 等最终动作。

## 11. 验收基线

当前阶段后续修改不应破坏以下基线：

1. 临床安全语义抽取生产主路径使用 LiteLLM `response_format`。
2. LLM 输出必须经过 Pydantic 契约校验。
3. 结构化响应非法时，不进行字符串修复或宽松字段补全。
4. LLM 禁用、不可用、失败或低置信时，不启用硬编码关键词事实兜底。
5. 不可信语义不生成召回增强 hints。
6. 语义状态和降级原因可在 metadata 中观察。
7. 语义抽取失败时，临床安全候选召回仍可使用用户原文和可信宠物上下文继续尝试。
8. 临床安全语义抽取和临床安全候选召回保持边界独立。
9. 临床安全语义抽取和临床安全裁决保持边界独立。
10. 默认快速 CI 不要求真实外部服务，真实服务冒烟测试需显式开启。
