# 幂等与 Turn Lock 变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：主业务对话入口、单回合执行门禁、调用方幂等重试、后续业务模块接入
>
> **不适用范围**：软件包内部存储结构、数据库迁移、锁实现、问诊状态机、临床安全裁决、RAG、记忆和报告领域内部实现

## 1. 变更目的

本次迁移将幂等控制和同会话回合串行能力从 Agent 主业务编排中独立出来，收束为统一的回合执行门禁。

迁移前，主业务编排直接处理幂等 claim、响应重放、等待判断和失败标记，且本地文件、进程内状态与生产级持久化状态之间存在多套可信路径。后续多实例部署、功能迁移和调用方重试都容易受到并发状态不一致影响。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 回合执行门禁 | 可信基础设施能力 | 主业务链路入口之前 | 建立单回合执行边界，统一处理并发与幂等行为 |
| 会话范围串行 | 可信基础设施能力 | 已授权会话范围内 | 保护问诊状态、回合记忆和响应顺序 |
| 幂等键 | 调用方提供的重试标识 | `turn_options.idempotency_key` | 标识一次可重试的业务请求 |
| 业务语义一致性 | 服务端判定的幂等一致性条件 | 执行门禁内部 | 判断重复请求应重放、等待、执行或拒绝 |
| 成功结果重放 | 可信执行结果 | 首个成功回合之后 | 为同语义重试返回首个成功回合结果 |

## 2. 职责边界

### 2.1 调用方职责

调用方负责在需要安全重试时提供稳定幂等键。

调用方必须：

1. 为同一次业务请求的重试复用同一个幂等键。
2. 避免在同一幂等键下修改输入、附件、模型、宠物范围、业务选项或其他可能影响响应结果的字段。
3. 将幂等冲突视为调用方键使用错误，不应对原请求继续自动重试。
4. 在仍在处理、超时或服务暂时不可用时使用退避策略重试。
5. 不在幂等请求失败后删除幂等键并立即提交相同业务请求。

调用方不负责：

1. 判断服务端是否已经执行过主业务链路。
2. 自行推断服务端重放结果是否可用。
3. 生成服务端内部并发控制状态。
4. 处理 Agent 内部会话状态串行化。

### 2.2 Agent 入口层职责

Agent 入口层负责将门禁产生的稳定错误语义转换为外部可观察行为。

入口层当前负责：

1. 保持 `turn_options.idempotency_key` 字段兼容。
2. 对同步接口返回稳定错误响应。
3. 对流式接口输出稳定的回合失败事件。
4. 保持主业务入口和 OpenAI 兼容入口的幂等语义一致。
5. 将调用方可理解的冲突、超时和不可用行为暴露出来。

入口层不负责：

1. 决定临床安全动作。
2. 修改问诊状态。
3. 生成或改写幂等键。
4. 为不同语义请求兼容重放历史结果。
5. 在门禁不可用时启用低一致性回退。

### 2.3 Agent 业务模块职责

临床安全、问诊、RAG、记忆、报告和策略等业务模块只消费“主回合已进入统一执行边界”这一事实。

业务模块可以依赖：

1. 主业务对话回合在进入领域处理前已经通过统一执行门禁。
2. 同一已授权会话范围内不会并发执行多个主业务回合。
3. 重复请求如果被重放，不会再次进入领域处理。
4. 幂等冲突不会交给领域模块自行判断。

业务模块不负责：

1. 读取或写入幂等内部状态。
2. 自行实现会话锁、幂等缓存、幂等表或关键词去重。
3. 根据幂等键改变临床判断、问诊决策、RAG 召回或记忆写入策略。
4. 将执行门禁视为外部副作用的分布式事务保证。

## 3. 接口兼容边界

### 3.1 已迁移的主业务入口

以下入口已统一经过回合执行门禁：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已迁移 | 主业务对话入口，继续通过 `turn_options.idempotency_key` 接收可选幂等键 |
| `POST /openai/v1/responses` | 已迁移 | OpenAI Responses 风格兼容入口，幂等语义与主业务入口一致 |

上述入口在未提供幂等键时仍会进入会话范围串行边界，但不会获得成功结果重放能力。

### 3.2 保持兼容的字段

以下字段为兼容保留，不属于本次迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `turn_options.idempotency_key` | 字段名、位置和可选语义保持不变 |
| `request_id` | 可在同一幂等请求重试时变化 |
| `trace_id` | 可在同一幂等请求重试时变化 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |
| `input` | 文本与 OpenAI 风格消息输入继续兼容 |
| `attachments` | 附件引用结构保持不变 |
| `metadata` | 继续作为业务请求语义的一部分传递 |

`request_id` 和 `trace_id` 是追踪字段，不应用于表达业务语义差异。调用方不应通过改变这两个字段绕过幂等语义。

### 3.3 暂未纳入本次迁移的接口

以下接口不属于主业务对话回合，不以本文档作为幂等和回合串行保证来源：

| 模块 | 当前状态 | 保留原因 |
|---|---|---|
| 报告解析与查询接口 | 不纳入主回合门禁 | 报告属于独立摄取和查询领域，需要单独定义幂等键和任务语义 |
| 记忆管理接口 | 不纳入主回合门禁 | 记忆管理属于人工纠正或后台治理领域，需要独立操作审计 |
| 管理后台接口 | 不纳入主回合门禁 | 管理操作需要单独定义运维主体、权限范围和重试策略 |
| 异步任务或事件消费者 | 不纳入主回合门禁 | 其生命周期不等同于主业务对话回合 |

这些保留路径不是主业务对话入口的回退机制。

## 4. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收调用方幂等键、请求标识、追踪标识和业务输入 |
| 范围授权 | 先完成用户、宠物与会话范围授权，确定可信会话范围 |
| 回合执行门禁 | 在进入主业务链路前处理会话串行、幂等重放、冲突和等待行为 |
| 领域主链路 | 执行临床安全、问诊、RAG、回复生成、记忆写入和 trace 留痕 |
| 成功结果固化 | 主链路成功后形成可重放的完整回合结果 |
| 错误映射 | 将冲突、超时、不可用和业务异常转换为同步或流式入口可观察结果 |

后续模块应把回合执行门禁视为“主业务链路入口的统一前置边界”，而不是某个领域内部工具。

## 5. 幂等键语义

幂等键的准确定位是：

```text
调用方为同一次可重试业务请求提供的稳定重试标识
```

幂等键的用途：

1. 将同一次业务请求的多次提交关联起来。
2. 在首个请求成功后，为后续同语义请求返回首个成功结果。
3. 在首个请求仍在处理时，避免并行执行第二次主业务回合。
4. 在同一键承载不同业务语义时拒绝请求。
5. 支持调用方在网络超时、客户端重试或网关重放场景下安全恢复。

幂等键不得用于：

1. 表达用户、宠物或会话身份。
2. 绕过范围授权。
3. 改变临床安全、问诊、RAG 或记忆策略。
4. 将不同业务语义兼容为同一次请求。
5. 让服务端根据自然语言自动生成或猜测请求身份。

## 6. 回合串行语义

当前回合串行策略的含义是：

```text
同一已授权会话范围内的主业务对话回合按顺序执行
```

该策略的作用是：

1. 防止同一会话内多个请求并发修改问诊状态。
2. 防止回合记忆和 trace 顺序与用户实际交互顺序不一致。
3. 防止重复请求在首个请求未完成时并行进入主业务链路。
4. 为后续问诊状态、记忆写入和响应重放提供稳定前置边界。

该策略不表示：

1. 同一用户全局只能同时咨询一个宠物。
2. 同一宠物全局只能有一个会话。
3. 不同会话之间必须串行。
4. 后台任务、管理操作或异步消费者自动受主回合门禁保护。
5. 所有数据库写入和外部服务调用具备 exactly-once 事务保证。

## 7. 有意保留的 TODO

以下 TODO 会影响调用方或跨领域协作，因此有意保留在本对齐文档中：

| TODO | 边界说明 | 后续建议 |
|---|---|---|
| BFF 幂等键规范 | 当前只要求调用方提供稳定且可复用的幂等键 | 在对外 API 契约中补充生成规则、长度、生命周期和重试窗口 |
| 处理中错误语义 | 当前对外表现为等待超时 | 如调用方需要区分业务超时与重复请求仍在处理，可增加专用错误码 |
| 跨领域副作用一致性 | 当前不承诺数据库写入、外部 API、事件发布之间的分布式原子性 | 引入 outbox、领域级去重或补偿机制前，先定义失败和重试契约 |
| 异步任务边界 | 当前主回合门禁不自动覆盖回合结束后的异步任务 | 后续每类异步任务应定义自己的业务键、重试和去重策略 |
| 响应重放数据治理 | 当前重放完整成功回合结果 | 后续结合隐私、保留周期和字段演进定义统一治理策略 |
| 多区域一致性 | 当前仅承诺单一部署一致性域内的幂等与回合串行行为 | 跨区域部署前定义全局一致性等级、路由粘性和故障切换行为 |
| 可观察性契约 | 当前对外提供冲突、超时和不可用错误 | 后续补充重放次数、等待耗时和冲突率等统一指标，不暴露内部状态结构 |

## 8. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不把幂等机制作为问诊状态机或业务任务状态机。
2. 不把执行门禁作为消息队列、任务调度器或工作流引擎。
3. 不保证不同会话之间的全局执行顺序。
4. 不保证所有数据库和外部服务副作用 exactly once。
5. 不替代模型调用、RAG、记忆、报告或异步任务自身的重试和一致性设计。
6. 不由服务端根据请求文本自动生成或猜测幂等键。
7. 不允许不同业务语义通过同一幂等键兼容重放。
8. 不承诺流式传输分片与首次请求逐字节、逐时序一致。
9. 不公开或约束软件包内部存储结构、锁算法、数据模型和调用栈实现。

## 9. Fail Fast 规则

主业务入口遇到以下情况应拒绝请求，而不是进入兼容兜底：

| 场景 | 预期行为 |
|---|---|
| 执行门禁依赖不可用 | 拒绝进入主业务链路 |
| 同一幂等键承载不同业务语义 | 返回冲突错误 |
| 首个请求仍在处理且等待窗口耗尽 | 返回超时语义 |
| 无法确认已有请求是否完成 | 不并行执行第二次主业务回合 |
| 业务模块尝试自行维护幂等状态 | 在代码评审中拒绝 |
| 业务模块尝试增加低一致性回退路径 | 在代码评审中拒绝 |
| 调用方在冲突后继续复用错误幂等键 | 继续返回冲突错误 |

测试环境可以显式注入替身，但测试替身必须遵守相同的可观察契约。

## 10. 后续实现对齐原则

后续迁移临床安全、问诊状态、RAG、记忆、报告、策略和异步任务时，应遵循以下约束：

1. 主业务对话中的领域处理必须位于统一执行门禁以内。
2. 需要表达调用方重试时，只使用 `turn_options.idempotency_key`，不新增并行幂等字段。
3. 领域模块不得读取、写入或推断幂等内部状态。
4. 领域模块不得自行实现会话锁、幂等表、幂等缓存或关键词去重。
5. 领域模块不得根据幂等键改变临床判断、问诊决策、RAG 召回或记忆写入策略。
6. 外部副作用、异步任务和事件发布需要各自定义业务键、重试和去重策略。
7. 调整请求字段语义时，应评估其是否影响幂等一致性，并同步更新外部契约和冲突测试。
8. 调整错误行为时，应同步更新同步接口、流式接口和调用方重试说明。
9. 需要管理接口扩展时，应定义专用幂等或任务语义，不复用主对话回合语义。

## 11. 验收基线

当前阶段后续修改不应破坏以下基线：

1. 无幂等键的主业务请求仍受同会话回合串行保护。
2. 相同会话范围、相同幂等键和相同业务语义只执行一次主业务回合。
3. 重复请求返回首个成功回合的标识和响应内容。
4. 相同幂等键承载不同业务语义时返回冲突。
5. 仍在处理的重复请求不会并行执行第二次主业务回合。
6. 执行门禁不可用时拒绝主业务请求，不启用低一致性回退。
7. 同步接口与流式接口遵守一致的幂等、冲突和不可用语义。
8. 后续业务模块不需要了解存储方式、锁算法、数据模型或软件包内部调用路径。
9. 主业务入口响应结构、流式协议和幂等键字段位置保持兼容。
