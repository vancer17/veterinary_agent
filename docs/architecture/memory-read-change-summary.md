# 记忆读取变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：Agent 主业务对话入口、记忆读取数据链、回复生成上下文、旧版记忆查询兼容接口、真实外部 API 集成测试
>
> **不适用范围**：长期记忆写入策略、记忆候选抽取、宠物资料纠正流程、报告解析、医学 RAG 检索、临床安全最终裁决和管理后台完整治理

## 1. 变更目的

本次迁移将记忆读取从旧版松散 `dict` 读取、最近摘要拼接和 Mem0 读写混用路径中收束出来，改为“PostgreSQL 权威记忆读取 + Mem0 语义投影召回 + 分层上下文编译”的主路径。

迁移前，记忆读取链路容易出现以下问题：

1. 当前会话、宠物长期事实、宠物历史 episode、问诊状态和语义记忆结果混在同一份松散结构内。
2. 回复生成 Agent 容易直接消费原始记忆字典，难以区分权威事实和语义线索。
3. Mem0 既可能被理解为记忆读取主源，也可能被误用为长期事实可信源。
4. 读取失败、语义投影不可用、语义召回空命中和显式禁用之间缺少稳定审计语义。
5. 后续记忆写入、问诊状态、RAG 和临床安全迁移时，容易重新形成自定义规则状态机或多可信源。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 权威长期事实 | 可信事实 | PostgreSQL `pet_memory_facts` | 进入回复上下文，作为已验证事实提示，不由 Mem0 覆盖 |
| 当前会话窗口 | 会话上下文 | PostgreSQL `conversation_turns` | 提供当前 session 最近对话上下文，不承担跨 session 语义召回 |
| 宠物历史 episode | 审计化历史摘要 | PostgreSQL `pet_memory_episodes` | 提供同一宠物跨 session 的中期事件摘要 |
| 问诊状态快照 | 活跃流程状态 | PostgreSQL `consultation_states` | 恢复当前 session 的问诊上下文，不写入 Mem0 |
| Mem0 语义投影 | 相关历史线索 | Mem0 REST API | 按本轮用户输入召回跨轮语义相关片段，仅作为线索 |
| 记忆读取审计 | 可观察状态 | 响应 metadata | 表示读取数量、语义投影状态、配置限制和降级情况 |
| 记忆提示词上下文 | 编译结果 | 回复生成前 | 供回复生成 Agent 使用，保持分层来源说明和字符预算 |

记忆读取只回答“当前回合在可信用户、宠物和会话范围内，可以读取哪些历史上下文”。它不负责决定哪些新事实应写入，不负责做临床安全裁决，不负责执行问诊状态机，也不负责替代医学 RAG。

## 2. 职责边界

### 2.1 记忆读取层职责

记忆读取层负责把当前可信身份范围转换为结构化记忆读取结果。

记忆读取层当前负责：

1. 按 `user_id + pet_id + session_id` 读取当前 session 最近对话。
2. 按 `user_id + pet_id` 读取权威长期事实和宠物历史 episode。
3. 读取当前 session 默认问诊状态和多任务问诊状态快照。
4. 在 Agent 主业务回合中使用本轮用户输入查询 Mem0 语义投影。
5. 汇总读取数量、语义投影状态、限制参数和降级状态。
6. 为旧版记忆查询接口提供结构化快照兼容输出。

记忆读取层不负责：

1. 根据关键词、症状、疾病名称或硬编码短语筛选记忆。
2. 在 Mem0 不可用时自行构造语义召回结果。
3. 根据当前输入生成长期事实候选。
4. 判断事实冲突、事实可信度升级或宠物资料纠正。
5. 执行临床安全升级、阻断、急诊或用药裁决。
6. 将开发样例 JSON、seed 文件或静态资产作为生产记忆来源。
7. 绕过仓储协议直接暴露数据库表模型给业务层。

### 2.2 PostgreSQL 权威记忆职责

PostgreSQL 是当前记忆读取的数据可信底座。

PostgreSQL 当前负责：

1. 保存长期事实、事实来源、置信度和附加审计信息。
2. 保存当前 session 已完成回合的用户输入与回复摘要。
3. 保存同一宠物的中期 episode。
4. 保存当前 session 的活跃问诊状态。
5. 支持后续纠正、删除、审计和迁移脚本形成稳定数据边界。

PostgreSQL 不负责：

1. 执行跨轮语义相关性召回。
2. 替代 Mem0 维护语义投影索引。
3. 替代 OPA 执行记忆写入、删除或纠正策略裁决。
4. 替代 LlamaIndex 或知识库 RAG 提供医学知识证据。
5. 根据自然语言原文动态推导未落库事实。

### 2.3 Mem0 语义投影职责

Mem0 在本阶段的定位是“语义记忆投影”，不是权威事实库。

Mem0 当前负责：

1. 按当前回合用户输入执行语义召回。
2. 通过用户和宠物范围过滤语义投影结果。
3. 返回与本轮主诉可能相关的历史线索。
4. 支持跨 session 的语义相关记忆补充。
5. 在响应 metadata 中暴露是否查询、是否空命中或是否降级。

Mem0 不负责：

1. 覆盖 PostgreSQL 中的权威长期事实。
2. 保存活跃问诊状态、幂等状态、turn lock 或策略结果。
3. 作为临床安全候选或最终医疗动作的唯一依据。
4. 在返回结果缺少当前用户或宠物范围时被宽松接受。
5. 失败后通过本地关键词、最近摘要或固定 query 进行替代召回。
6. 直接产生可写入 `pet_memory_facts` 的权威事实。

### 2.4 上下文编译职责

记忆上下文编译层负责把结构化读取结果转换为回复生成 Agent 可消费的提示词片段。

上下文编译层当前负责：

1. 保持“已验证长期事实、当前会话上下文、宠物历史事件、相关历史线索、当前问诊状态”的分层呈现。
2. 将 Mem0 召回结果明确标记为语义线索，而不是已验证事实。
3. 根据 `MEMORY_PROMPT_MAX_CHARS` 控制提示词字符预算。
4. 生成可进入响应 evidence 的记忆读取证据摘要。
5. 向响应 metadata 输出提示词长度和读取审计摘要。

上下文编译层不负责：

1. 重新排序医疗风险优先级。
2. 诊断疾病、判断严重程度或生成治疗方案。
3. 把语义线索提升为长期事实。
4. 根据上下文内容改变问诊状态。
5. 通过摘要压缩模型重新生成记忆内容。
6. 使用不可追溯的自然语言规则筛选记忆。

### 2.5 主链路职责

主业务编排层负责在安全链路放行后读取记忆，并把编译后的上下文交给后续问诊与回复生成阶段。

主链路当前负责：

1. 在身份范围、turn lock、基础输入安全、宠物上下文和临床安全裁决之后执行记忆读取。
2. 在进入任务拆分、问诊语义抽取、问诊状态更新和回复生成前获得结构化记忆上下文。
3. 使用读取到的问诊状态判断是否延续当前 session 的未完成问诊。
4. 将记忆读取摘要写入响应 metadata。
5. 在多任务回合中复用同一轮读取到的记忆上下文，避免每个任务重复查询。

主链路不负责：

1. 直接读取记忆数据库表。
2. 直接调用 Mem0 REST API。
3. 根据记忆内容跳过临床安全或基础输入安全。
4. 在记忆读取失败时自行拼接旧版 `last_summary` 兜底。
5. 将记忆读取结果直接写入长期事实。

## 3. 接口兼容边界

### 3.1 已覆盖的主业务入口

以下入口继续使用既有请求和响应结构，无需调用方新增字段：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已覆盖 | 主业务对话入口，在临床安全放行后读取记忆上下文 |
| `POST /openai/v1/responses` | 已覆盖 | OpenAI Responses 风格兼容入口，与主业务入口使用同一记忆读取语义 |

记忆读取迁移不改变入口请求字段。调用方仍通过既有 `input`、`scope_assertion`、`vet_context`、`attachments`、`metadata`、`model`、`stream` 和 `turn_options` 提交请求。

### 3.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次记忆读取迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 继续作为用户本轮原文来源；Agent 主回合中用于 Mem0 语义召回 query |
| `scope_assertion` | 继续作为可信用户、宠物和 session 范围来源 |
| `scope_assertion.profile` | 继续作为服务端可信宠物画像来源；不由记忆读取覆盖 |
| `vet_context.pet_info` | 继续作为未验证资料兼容字段；不得作为记忆读取范围或事实可信源 |
| `metadata` | 继续作为审计透传字段；不得作为记忆召回硬规则来源 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |

后续如需调用方显式控制记忆读取范围、召回策略或上下文预算，应通过独立接口契约评审，不应复用 `metadata` 作为隐式控制面。

### 3.3 旧版记忆查询接口兼容

`GET /memories` 继续保留旧版三段式响应结构，用于管理、排障和兼容调用方读取快照。

兼容结构保持为：

| 响应字段 | 当前语义 |
|---|---|
| `owner` | 当前保留为空对象，不作为本阶段迁移范围 |
| `pet.last_summary` | 当前 session 最近一轮摘要 |
| `pet.turns` | 当前可信用户、宠物和 session 范围内的最近回合 |
| `pet.facts` | 当前可信用户和宠物范围内的权威长期事实 |
| `pet.episodes` | 当前可信用户和宠物范围内的中期 episode |
| `pet.semantic_memories` | 兼容字段；管理快照不触发 Mem0 语义查询，通常为空 |
| `session.last_summary` | 当前 session 最近一轮摘要 |
| `session.turns` | 当前 session 最近回合 |
| `session.consultation_state` | 当前 session 默认问诊状态 |
| `session.task_consultation_states` | 当前 session 多任务问诊状态集合 |

重要边界：

1. `GET /memories` 是快照读取接口，不使用固定 query 或最近摘要触发 Mem0 语义召回。
2. `GET /memories` 保留既有 `user_id`、`pet_id`、`session_id` 查询参数和授权方式。
3. `PUT /memories`、`PUT /memories/facts` 和 `DELETE /memories/pets/{pet_id}` 的写入、纠正和删除职责不属于本次读取迁移。
4. 管理接口后续应结合管理主体、范围声明和记忆治理策略单独迁移，不复用主业务对话入口的 `scope_assertion` 语义。

### 3.4 稳定的响应可观察字段

记忆读取通过响应 metadata 和 evidence 对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.memory_read` | 本轮结构化记忆读取摘要 |
| `metadata.memory_read.audit.purpose` | 读取目的，主业务回合为 `agent_turn` |
| `metadata.memory_read.audit.facts_count` | 读取到的权威长期事实数量 |
| `metadata.memory_read.audit.session_turns_count` | 当前 session 滑动窗口回合数量 |
| `metadata.memory_read.audit.pet_episodes_count` | 宠物中期 episode 数量 |
| `metadata.memory_read.audit.semantic_recollections_count` | Mem0 语义召回数量 |
| `metadata.memory_read.audit.semantic_status` | Mem0 语义投影读取状态 |
| `metadata.memory_read.audit.degraded` | 记忆读取是否存在显式降级 |
| `metadata.memory_read.has_consultation_state` | 当前 session 是否存在默认问诊状态 |
| `metadata.memory_read.task_consultation_state_count` | 当前 session 多任务问诊状态数量 |
| `metadata.memory_context` | 进入回复生成前的记忆提示词上下文审计 |
| `metadata.multi_agent_path` | 主链路中应包含 `MemoryAgent` |
| `evidence.source=结构化记忆读取` | 表示回复上下文中使用了记忆读取证据摘要 |

后续模块应依赖上述稳定字段进行跨领域对齐，不应依赖内部类名、SQL 查询细节、Mem0 原始响应、测试替身或调用栈顺序。

### 3.5 暂未纳入本次迁移的接口

以下接口或领域不以本文档作为最终契约来源：

| 模块 | 当前状态 | 保留原因 |
|---|---|---|
| 长期记忆写入 | 待迁移 | 写入候选抽取、冲突处理和策略裁决需要独立 OPA 边界 |
| 记忆纠正与删除治理 | 保留既有接口 | 人工纠正、删除审计和 Mem0 投影清理需要单独管理策略 |
| 报告解析 | 暂未纳入 | 报告结构化结果属于独立摄取域，不直接进入记忆读取主路径 |
| 管理后台 | 暂未完整实现 | 管理主体、权限范围、审计和批量治理需要单独设计 |
| RAG 知识问答 | 保留独立链路 | RAG 面向医学知识证据，不由记忆读取替代 |
| 临床安全裁决 | 已独立迁移 | 临床安全动作不能依赖 Mem0 记忆作为唯一依据 |

这些保留路径不是记忆读取失败时的隐式回退机制。

## 4. 记忆分层语义

迁移后的记忆读取结果保持固定分层，后续实现应优先按分层语义消费。

| 分层 | 当前含义 | 使用边界 |
|---|---|---|
| `authoritative_facts` | PostgreSQL 权威长期事实 | 可作为已验证历史事实提示；如与当前可信画像冲突，不得覆盖 `scope_assertion.profile` |
| `recent_session_turns` | 当前 session 最近回合窗口 | 用于理解当前对话延续关系；不表示跨 session 完整病史 |
| `recent_pet_episodes` | 同一宠物的中期历史事件摘要 | 用于补充跨 session 历史背景；不替代权威事实表 |
| `semantic_recollections` | Mem0 语义投影召回 | 仅作为相关历史线索；不得直接升级为权威事实或临床动作 |
| `consultation_state` | 当前 session 默认问诊状态 | 用于恢复未完成问诊；不属于长期记忆事实 |
| `task_consultation_states` | 当前 session 多任务问诊状态 | 用于多任务问诊延续；不属于 Mem0 投影内容 |
| `audit` | 本次读取审计摘要 | 用于响应可观察性、CI 断言和排障 |

准确定位如下：

```text
记忆读取不是“把所有历史拼进 prompt”，而是在可信范围内按来源可信度分层读取，并把每一层以受控语义交给后续 Agent。
```

## 5. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收用户原文、可信范围声明、未验证宠物资料审计副本和幂等键 |
| 范围授权与 turn lock | 确定可信用户、宠物和 session 范围，并进入统一回合执行边界 |
| 基础输入安全 | 先裁决输入完整性、附件能力边界和提示注入等非临床输入风险 |
| 宠物上下文加载 | 只加载服务端可信宠物画像，不用请求侧 `pet_info` 覆盖 |
| 临床安全语义、候选与裁决 | 在普通问诊链路前完成临床安全结构化处理和策略裁决 |
| 记忆读取 | 读取 PostgreSQL 权威记忆、问诊状态和 Mem0 语义投影 |
| 记忆上下文编译 | 分层编译为回复生成可消费的提示词上下文 |
| 任务拆分与问诊状态更新 | 使用读取到的问诊状态判断是否延续当前 session |
| RAG 与回复生成 | 在医学知识证据之外补充历史记忆上下文 |
| 响应审计 | 写入记忆读取数量、语义投影状态、提示词上下文审计和多 Agent 路径 |
| 记忆写入 | 回合结束后按既有写入链路处理，本次迁移不改变写入策略 |

后续领域模块应把记忆读取视为“回复生成与问诊延续前的历史上下文读取边界”，不是长期事实写入器、临床安全裁决器、RAG 检索器或问诊状态机本体。

## 6. 降级与 Fail Fast 规则

记忆读取迁移后的核心原则是：权威记忆读取失败应 Fail Fast；Mem0 语义投影失败只有在显式配置允许时才可降级。

允许的降级：

1. `ENABLE_MEM0=false` 时，语义投影状态为 `disabled`，主链路继续使用 PostgreSQL 权威记忆和问诊状态。
2. Agent 主回合查询 Mem0 但无命中时，语义投影状态为 `empty`，不伪造语义线索。
3. 管理快照读取不触发 Mem0 语义查询，语义投影状态可为 `skipped` 或 `disabled`。
4. `MEMORY_READ_ALLOW_SEMANTIC_DEGRADED=true` 时，Mem0 调用失败可记录为 `degraded` 并继续主链路。
5. 提示词上下文超出 `MEMORY_PROMPT_MAX_CHARS` 时，可以按字符预算截断展示内容，但不得改变底层读取结果。
6. 无 `DATABASE_URL` 的开发、测试或特殊嵌入场景可以使用 JSON 仓储兼容路径，但不得作为生产运行回退。

不允许的降级：

1. 不允许 PostgreSQL 权威记忆读取失败时静默返回空记忆并继续主链路。
2. 不允许 Mem0 查询失败时用关键词、最近摘要、固定 query 或开发样例补造语义召回。
3. 不允许 Mem0 返回结果缺少或不匹配当前 `user_id + pet_id` 范围时宽松接收。
4. 不允许把 `vet_context.pet_info`、请求 metadata 或用户自然语言中的宠物信息作为记忆读取范围。
5. 不允许把 Mem0 语义线索直接写入权威事实或问诊状态。
6. 不允许把旧版 `last_summary` 作为替代语义召回机制。
7. 不允许由记忆读取层实现症状规则、疾病判断或临床状态机。

Fail Fast 的含义不是所有记忆为空时停止回答，而是依赖不可用、范围不一致或返回契约非法时不能制造可信上下文。系统可以在真实“无历史记忆”的情况下继续回答，但不能把失败伪装成空命中。

## 7. 配置与运行边界

当前记忆读取相关配置保持有限集合：

| 配置 | 当前默认 | 作用 |
|---|---|---|
| `DATABASE_URL` | 未设置 | 设置后使用 PostgreSQL 权威记忆读取主路径 |
| `ENABLE_MEM0` | `true` | 是否启用 Mem0 语义投影读写能力 |
| `MEM0_BASE_URL` | `http://127.0.0.1:8001` | Mem0 REST API 基础地址 |
| `MEM0_API_KEY` | 未设置 | Mem0 API 鉴权密钥，敏感参数应通过 env 注入 |
| `MEMORY_READ_SESSION_TURN_LIMIT` | `20` | 当前 session 最近回合读取上限 |
| `MEMORY_READ_PET_EPISODE_LIMIT` | `10` | 当前宠物中期 episode 读取上限 |
| `MEMORY_READ_SEMANTIC_LIMIT` | `5` | Mem0 语义投影召回上限 |
| `MEMORY_READ_ALLOW_SEMANTIC_DEGRADED` | `false` | 是否允许 Mem0 失败时显式降级继续 |
| `MEMORY_PROMPT_MAX_CHARS` | `5000` | 回复生成前记忆上下文字符预算 |

运行边界：

1. 生产环境应设置 `DATABASE_URL`，并通过 Alembic 维护记忆相关表结构和字段注释。
2. 敏感参数只通过 env 或 GitHub Environment 注入，不写入仓库内配置文件。
3. 服务型配置应保持在 Docker Compose、应用配置 yml 或运行环境变量边界内，不在业务代码中硬编码。
4. Mem0 是外部依赖服务，真实服务集成测试应显式开启，不作为默认快速 PR 门禁的隐式依赖。
5. 调整读取上限和提示词预算时，应同步评估响应延迟、模型上下文占用和记忆泄露风险。

## 9. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不把 Mem0 改造成权威事实库。
2. 不把 PostgreSQL 最近回合窗口改造成手写语义记忆搜索引擎。
3. 不在记忆读取层实现关键词、症状、疾病或临床安全规则。
4. 不使用开发样例 JSON、seed 文件或仓库静态资产作为生产记忆读取主路径。
5. 不让 `vet_context.pet_info` 或请求 metadata 改变记忆读取范围。
6. 不让旧版 `/memories` 管理快照触发隐式 Mem0 语义查询。
7. 不在 Mem0 失败时用本地规则、固定 query 或 `last_summary` 伪造召回结果。
8. 不把记忆读取结果直接写入长期事实。
9. 不让记忆读取替代医学 RAG 知识证据。
10. 不让记忆读取绕过基础输入安全、临床安全或 turn lock。

## 10. 后续实现对齐原则

后续迁移记忆写入、问诊状态、RAG、输出安全和管理治理时，应遵循以下约束：

1. 记忆读取结果应按来源分层消费，不应重新合并为无来源的松散字典。
2. PostgreSQL 权威事实、当前 session 回合、宠物 episode、问诊状态和 Mem0 语义投影应保持不同可信等级。
3. Mem0 只提供语义相关线索，不直接产生权威事实、策略动作或问诊状态。
4. 任何写入长期事实的路径都应经过候选抽取、结构校验和策略裁决，不得由读取链路反向写入。
5. 当前会话窗口只表示对话延续上下文，不应被扩展成跨 session 规则状态机。
6. 问诊状态属于活跃流程状态，不应写入 Mem0，也不应作为长期事实保存。
7. 医学 RAG 仍应依赖知识库证据，记忆上下文只能描述历史个体信息和历史线索。
8. 外部接口应依赖 `metadata.memory_read` 与 `metadata.memory_context`，不依赖内部包名或 Mem0 原始响应。
9. 新增配置项前应先判断是否已有明确消费方，避免悬空配置。
10. 新增测试应区分本地契约测试、真实服务集成测试和生产发布前冒烟测试。

## 11. 验收基线

当前阶段后续修改不应破坏以下基线：

1. Agent 主业务回合在临床安全放行后执行结构化记忆读取。
2. 记忆读取必须按可信 `user_id + pet_id + session_id` 范围执行。
3. PostgreSQL 权威记忆读取失败时应 Fail Fast。
4. Mem0 语义投影只按当前用户输入查询，不使用硬编码 query 或旧版 `last_summary` 回退。
5. Mem0 返回结果必须满足当前用户和宠物范围校验。
6. Mem0 禁用、空命中、跳过和显式降级状态应可在 metadata 中观察。
7. 回复生成只消费分层编译后的记忆提示词上下文，不直接消费松散原始字典。
8. 旧版 `GET /memories` 查询接口保持三段式兼容结构。
9. 管理快照读取不触发 Mem0 语义查询。
10. 默认快速 CI 不要求真实外部服务；真实记忆读取 API 测试需显式开启。
11. 记忆读取不使用开发样例 JSON、seed 文件或仓库静态资产作为生产主路径。
12. 记忆读取和长期记忆写入保持职责独立。
