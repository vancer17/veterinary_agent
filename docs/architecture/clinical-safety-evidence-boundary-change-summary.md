# 临床安全证据充分性边界变更总结

> **文档状态**：阶段 1 迁移完成后的对齐基线
>
> **适用范围**：临床安全语义、候选强召回准入、OPA 候选升级准入、响应 metadata 审计
>
> **不适用范围**：疾病诊断、治疗建议、完整症状标准化、复杂 `required_context` 组合语义、
> 资产 code 治理、主安全信号排序和医学资产运营后台

## 1. 变更目的

本次迁移将“用户希望获得分诊建议”与“当前回合已提供可用于临床安全候选裁决的正向事实”明确分离。

此前，`intent_type=triage`、症状/暴露状态、高风险短语和候选相似度可能在不同位置被重新组合，容易使模糊提问被解释为已经存在急诊风险。本阶段以单一结构化字段收束这一准入判断：

```text
risk_evidence_state
```

该字段是临床安全候选进入强召回和升级裁决面的前置条件，不是疾病标签、急诊等级、诊断结论或用户可见动作。

## 2. 稳定职责边界

### 2.1 `risk_evidence_state` 契约

| 值 | 稳定语义 | 临床安全链路行为 |
|---|---|---|
| `sufficient` | 当前回合存在可信的正向症状、暴露或其他风险事实 | 可以进入强候选召回和后续候选裁决 |
| `insufficient` | 当前回合可信，但只是分诊、知识、预防或假设性提问，缺少正向风险事实 | 不生成有效 urgent 候选信号；主链路可以继续追问或普通处理 |
| `unknown` | 语义抽取失败、置信度不足、契约不完整或无法可靠判断 | 临床安全候选升级路径显式降级 |

以下不改变：

1. `risk_evidence_state` 不表达具体疾病或风险模式。
2. `risk_evidence_state=sufficient` 只表示“允许评估候选”，不保证任何候选最终升级。
3. `risk_evidence_state=insufficient` 不表示宠物安全，只表示本回合尚无足够事实进行强临床安全裁决。
4. `risk_evidence_state=unknown` 不得被旧字段、关键词或候选分数补写为其他值。

### 2.2 各领域职责

| 领域 | 稳定职责 | 明确不承担的职责 |
|---|---|---|
| 临床安全语义抽取 | 基于用户本轮输入与可信宠物上下文输出证据状态和结构化事实摘要 | 不输出急诊、阻断、追问或诊断动作 |
| 候选召回 | 仅在可信且证据充分时构造强召回输入并获取已审核候选 | 不从原始文本、画像或静态资产直接生成临床事实 |
| OPA 临床安全裁决 | 消费可信语义状态、候选及其结构化上下文，决定候选是否可以升级 | 不重新组合旧字段推导风险证据，不扫描用户原文，不生成候选 |
| 主链路与响应投影 | 消费策略结果，并在证据不足时继续既有问诊或 observe 路径 | 不根据 `triage` 意图、候选分数或审计短语重新升级 |

因此，`risk_evidence_state` 是语义域向候选与策略域提供的“准入事实”，不是在 Python、OPA 或资产库中分散实现的另一套临床状态机。

### 2.3 不再具有升级资格的字段

以下字段仍可用于审计、召回解释或后续结构化处理，但不能单独证明当前回合存在临床高危事实：

| 字段 | 允许用途 | 禁止用途 |
|---|---|---|
| `intent_type=triage` | 表示用户希望获得分诊 | 直接进入急诊升级路径 |
| `high_risk_terms` | 语义抽取审计、候选解释 | 作为风险证据的替代值 |
| `matched_terms` | 向量召回解释、审计 metadata | 作为用户已经出现症状或暴露的证明 |
| `candidate.score` | 候选相关度与排序参考 | 补足缺失的临床事实或直接升级 |
| 宠物画像 | 后续适用性过滤、裁决上下文或受控弱增强 | 在无明确本轮事实时单独触发强召回或急诊 |

## 3. 对外与跨模块兼容

### 3.1 主业务 API 保持兼容

以下入口无需调用方新增请求字段：

| 接口 | 兼容状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 保持兼容 | 仍通过既有请求进入完整临床安全链路 |
| `POST /openai/v1/responses` | 保持兼容 | 与主业务入口使用同一临床安全证据边界 |

现有 `input`、`scope_assertion.profile`、`vet_context.pet_info`、`metadata`、`attachments` 与 `turn_options` 的请求契约不因本次迁移改变。未验证的 `vet_context.pet_info` 和 `metadata` 仍不得成为临床安全权威事实来源。

### 3.2 响应可观察字段

响应主结构、既有状态和 `safety_signals` 结构保持兼容。本阶段新增或稳定以下审计信息：

| 字段 | 语义 |
|---|---|
| `metadata.clinical_safety_semantic.risk_evidence_state` | 本轮结构化证据充分性状态 |
| `metadata.clinical_safety_semantic.fallback_state` | 语义抽取可信度与显式降级状态 |
| `metadata.clinical_safety_resolution.fallback_state.semantic` | 临床安全链路消费的语义状态摘要 |
| `metadata.clinical_safety_resolution.fallback_state.retrieval` | 本轮是否执行强候选召回及其状态 |
| `metadata.clinical_safety_resolution.policy_decision` | OPA 的动作、原因和安全信号审计摘要 |

调用方不得把“没有 urgent 信号”解释为医学安全结论，也不得从用户可见文本反推全部候选。候选与降级原因应通过 `safety_signals` 和上述 metadata 审计字段读取。

### 3.3 内部语义契约的有意不兼容

`risk_evidence_state` 是临床安全结构化语义的必填字段。缺失、非法或低置信的结构化响应不再由旧字段组合出兼容值，而是进入 `unknown` 与显式降级状态。

这是有意保留的 Fail Fast 兼容破坏，仅影响内部语义提供方和测试替身，不改变外部 HTTP 请求契约。后续新增该契约的生产或测试实现时，必须显式提供有效枚举值。

### 3.4 OPA 输入边界

Python 到 OPA 的稳定语义边界包含可信状态和 `risk_evidence_state`。OPA 可以据此拒绝候选升级，但不得通过症状状态、暴露状态、分诊意图、高风险短语或候选相似度重新构造“证据是否充分”的结论。

OPA 输入不包含用户原始全文。此约束防止策略层演变为关键词解析器，并保证自然语言事实抽取只有一个可信来源。

## 4. Fail Fast 与显式降级

以下情况必须停止临床安全候选升级路径：

1. 结构化响应缺少或包含非法的 `risk_evidence_state`。
2. 结构化语义置信度未达到可信门槛。
3. 语义抽取被禁用、依赖不可用或调用失败。
4. `risk_evidence_state=insufficient`。
5. `risk_evidence_state=unknown`。

在上述场景中：

1. 不执行由临床安全语义增强的强候选召回。
2. 不因候选 `severity`、`action_class`、`score` 或 `matched_terms` 生成 urgent 或 blocked 信号。
3. 不启用关键词、正则、资产短语、旧字段组合或 Python 本地医学规则回退。
4. 主 Agent 不会因此伪造临床安全结论；其后续是否追问或普通回复仍由既有领域职责决定。

Fail Fast 的目标是停止将不可信输入包装为可信临床事实，而不是把所有信息不足的会话视为系统错误或医学安全结论。

## 5. 有意保留的 TODO

以下内容不属于本阶段交付。后续实现必须以替代式迁移收束，而不是在现有边界旁新增关键词、code 分支或本地状态机。

| TODO | 当前边界 | 后续对齐要求 |
|---|---|---|
| 召回正文与画像上下文彻底拆分 | 本阶段只保证无充分证据时不触发强召回；不承诺所有画像字段已从语义增强文本中完全移除 | 阶段 2 应建立独立的“可嵌入事实文本”和“结构化适用性上下文”契约 |
| `observed_features` 或等价事实集合 | 目前没有可作为长期稳定契约的标准化症状/暴露事实集合 | 应由受控结构化抽取产出，OPA 仅进行集合关系判断，不扫描原文 |
| `required_context` 组合语义 | 当前只建立证据充分性准入，不定义完整 `all_of`、`any_of`、否定和未知值语义 | 应先扩展资产契约与结构化事实契约，再实现通用策略匹配 |
| 风险模式 code 治理与主信号排序 | 本阶段不拆分具体急诊模式，也不定义同级候选排序 | 应由资产治理和统一响应投影阶段处理；`code` 不能成为 Python 医学分支条件 |
| 语义质量与版本治理 | 当前保证结构化字段和失败语义，不代表已覆盖全部医学表达 | 应建立医学审核样本、版本兼容策略和真实服务契约测试 |

特别说明：当前任何 `high_risk_terms` 与候选前提之间的阶段性关联，都不得被后续模块视为正式的症状标准化契约。正式能力应由 `observed_features` 或等价受控事实模型替代。

## 6. 后续实现对齐约束

后续临床安全阶段必须持续满足以下约束：

1. 证据充分性只由受控结构化语义提供方输出；不得由候选层、OPA 或响应层重新推导。
2. 宠物画像是适用性上下文，不是本轮风险证据。
3. 召回结果是候选，不是临床事实；候选相似度不是风险等级。
4. `required_context` 必须消费结构化事实，不得退化为原始文本关键词匹配。
5. 资产 `code` 只标识资产身份，不得成为 Python 或 OPA 的疾病枚举分支。
6. OPA 只实现与资产无关的通用结构化准入、适用性和动作契约；不得访问原文、模型、数据库或 RAG。
7. 语义失败、低置信或新字段缺失时，必须保持 `unknown` 的显式降级，不恢复旧路径。
8. 任何新增字段都必须同步定义来源、允许值、可信状态、未知值、metadata 观察方式与 OPA 消费边界。

## 7. 验收基线

后续修改不得破坏以下已完成边界：

1. `triage` 意图本身不会触发临床安全升级。
2. 可信但 `insufficient` 的语义不会生成强召回提示或有效 urgent 信号。
3. `unknown`、低置信、失败、禁用或不完整语义不会由旧字段或关键词补写。
4. OPA 不通过原始文本、候选分数或审计短语推导风险证据。
5. 不可信语义下的候选不能仅凭自身严重级别或动作类别升级。
6. 外部 API 请求和响应主结构保持兼容，新增行为通过 metadata 可审计。
