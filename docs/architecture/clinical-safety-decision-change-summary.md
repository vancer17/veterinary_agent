# 临床安全裁决变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：临床安全裁决、OPA 策略输入输出、主业务安全升级分支、临床安全响应审计、真实外部 API 集成测试
>
> **不适用范围**：临床安全语义抽取内部实现、临床安全候选召回算法、医学 RAG 知识问答、问诊状态机、长期记忆写入、报告解析和管理后台资产治理

## 1. 变更目的

本次迁移将临床安全最终动作从 Python 业务层中的分散规则判断收束为“结构化输入组装 + OPA 策略裁决 + 严格结果校验”的策略门面。

迁移前，临床安全链路容易出现以下问题：

1. 候选召回、语义状态、上下文适用性和最终动作裁决混在同一层内。
2. Python 规则分支容易继续扩展为自定义临床安全状态机。
3. 低置信语义、否定语义、时间语义和上下文过滤可能被误用为隐式降级或升级依据。
4. OPA 接入后如果仍保留本地硬编码回退，会导致“两个裁决可信源”并存。
5. 真实服务联调难以区分“召回失败”“语义失败”“策略失败”和“主链路响应失败”。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 结构化临床语义 | 条件可信输入 | 临床安全语义抽取层 | 在可信时提供物种、暴露、症状、时间、否定和意图等策略输入 |
| 临床安全候选 | 可信候选输入 | PostgreSQL/pgvector 召回层 | 表达本轮可能相关的已审核临床安全资产候选 |
| 召回与语义状态 | 可审计运行状态 | 裁决输入与响应 metadata | 解释本轮裁决所依赖的数据质量和降级情况 |
| OPA 临床安全策略 | 可信动作裁决 | 临床安全裁决层 | 将结构化输入转换为 `allow`、`observe`、`escalate` 或 `block` |
| 策略结果校验 | 契约保护层 | OPA 客户端边界 | 拒绝不合法动作、信号、allow 组合和缺失字段 |

临床安全裁决只回答“基于已召回候选、可信语义和结构化上下文，本轮主链路应采取什么安全动作”。它不负责理解原始文本，不生成候选，不执行向量召回，也不生成医学诊断或治疗方案。

## 2. 职责边界

### 2.1 裁决层职责

临床安全裁决层负责把上游结构化结果转换为可审计动作。

裁决层当前负责：

1. 消费临床安全候选召回结果。
2. 消费结构化语义结果和显式语义降级状态。
3. 消费召回状态、候选分数、资产适用范围和阈值配置。
4. 调用 OPA Data API 获取最终动作、原因和安全信号。
5. 严格校验 OPA 返回结构，拒绝不合法响应。
6. 将策略决策写入 `metadata.clinical_safety_resolution.policy_decision`。
7. 在触发 `escalate` 或 `block` 时推动主链路进入安全分诊响应。

裁决层不负责：

1. 扫描用户原始文本。
2. 通过关键词、正则、词表或拼音同义词生成候选。
3. 在 pgvector 不可用或空命中时伪造临床安全候选。
4. 在 LiteLLM 语义失败或低置信时补造可信语义事实。
5. 组合症状推断疾病、诊断结论或治疗方案。
6. 读取长期记忆、RAG 知识库或开发样例作为最终动作依据。
7. 在 OPA 不可用或返回非法结果时回退本地硬编码裁决。

### 2.2 OPA 策略职责

OPA 是临床安全候选的最终动作裁决点，但不是临床文本理解引擎。

OPA 当前负责：

1. 只消费应用侧提交的结构化 `semantic`、`retrieval`、`candidates`、`thresholds` 和 `context`。
2. 根据候选严重级别、动作分类、候选分数和可信上下文适用性输出有限动作。
3. 在可信语义明确否认暴露、远期既往已恢复或上下文不适用时抑制对应候选。
4. 输出可审计的 `message`、`reasons` 和 `signals`。
5. 保持策略复杂度受控，使 Rego 更接近动作矩阵，而不是临床流程状态机。

OPA 不负责：

1. 读取或扫描原始用户文本。
2. 从原始文本、语义字段或静态资产中自行创建候选。
3. 维护自然语言关键词库、同义词库或正则匹配规则。
4. 执行医学推理，例如把“猫 + 发紫 + 呼吸急促”组合推断为某个疾病。
5. 访问业务数据库、Mem0、RAG 知识库或模型服务。
6. 生成自然语言医疗建议、诊断结论或用药剂量。

### 2.3 候选与语义的责任分离

临床安全裁决依赖上游输入，但不改变上游职责。

候选召回负责：

1. 从 PostgreSQL/pgvector 中召回已审核临床安全 chunk。
2. 输出候选资产、分数、来源和召回状态。
3. 在不可用或空命中时暴露降级原因。

语义抽取负责：

1. 使用 LiteLLM `response_format` 生成结构化语义。
2. 输出可信、低置信、失败、禁用或不可用状态。
3. 在可信时提供可进入召回和裁决的语义字段。

裁决层负责：

1. 接收候选、语义和状态。
2. 调用 OPA 得出动作。
3. 校验并透出策略结果。

任何后续实现都不应把这三层重新合并为一套 Python 规则状态机。

### 2.4 主链路职责

主业务编排层负责根据策略动作决定是否继续普通问诊链路。

主链路当前负责：

1. 在基础输入安全放行后加载可信宠物上下文。
2. 执行临床安全语义抽取和候选召回。
3. 将 OPA 裁决产生的临床安全信号合并进安全评估。
4. 在 `escalate` 或 `block` 时生成安全分诊响应。
5. 在临床安全升级响应中透出 `input_safety_decision` 与 `clinical_safety_resolution`。

主链路不负责：

1. 在 OPA 失败时自行判断安全动作。
2. 改写 OPA 策略结果。
3. 根据候选或语义字段新增隐藏动作分支。
4. 将临床安全裁决结果写入长期事实。
5. 将临床安全裁决替代问诊状态、RAG 证据或输出安全复核。

## 3. 策略输入边界

OPA 临床安全策略输入保持为结构化对象，不包含需要在策略层解析的原始长文本。

| 输入域 | 当前语义 | 边界说明 |
|---|---|---|
| `context` | 请求、用户、宠物和会话范围摘要 | 用于审计和策略追踪，不用于文本理解 |
| `semantic` | 临床安全结构化语义和可信状态 | 仅可信语义可参与否定、时间、暴露、适用性抑制 |
| `retrieval` | pgvector 召回运行状态 | 用于审计召回质量，不用于伪造候选 |
| `candidates` | 已召回临床安全候选 | OPA 唯一的候选来源 |
| `thresholds` | 策略动作阈值 | 区分信号阈值与升级阈值，不等同于召回阈值 |

重要约束：

1. `candidates` 为空时，OPA 不得根据文本或语义自行生成候选。
2. `semantic.trusted=false` 时，OPA 不得使用时间、否定、暴露状态执行抑制或降级。
3. `retrieval.degraded=true` 只表示召回质量降级，不表示可以启用本地规则补救。
4. `thresholds` 只控制候选到动作的策略门槛，不控制 embedding 召回过程。
5. `context` 不得成为业务越权或临床推理的隐式数据源。

## 4. 策略输出边界

临床安全策略输出保持有限动作集合。

| 动作 | `allow` | 当前语义 | 主链路行为 |
|---|---:|---|---|
| `allow` | `true` | 未识别到需要安全响应的临床安全候选 | 继续普通问诊链路 |
| `observe` | `true` | 记录低等级候选，但不阻断普通问诊 | 继续普通问诊链路，并保留审计信号 |
| `escalate` | `true` | 识别到需要优先线下处理的急性风险 | 生成安全分诊响应，停止普通问诊生成 |
| `block` | `false` | 识别到不应继续普通医疗回答的高风险场景 | 生成阻断或安全响应，停止普通问诊生成 |

策略结果必须满足以下契约：

1. `allow` 动作不得返回安全信号。
2. `observe` 动作不得返回 `urgent` 或 `blocked` 信号。
3. `escalate` 动作必须至少返回一个 `urgent` 信号。
4. `block` 动作必须至少返回一个 `blocked` 信号。
5. `block` 动作不得 `allow=true`。
6. 非 `block` 动作不得 `allow=false`。
7. `message`、`reasons` 和 `signals` 必须结构合法，否则 Fail Fast。

这些契约是 Python 与 OPA 之间的兼容接口。后续调整动作集合或信号语义时，应先更新契约、测试和本文档。

## 5. 接口兼容边界

### 5.1 已覆盖的主业务入口

以下入口继续使用既有请求和响应结构，无需调用方新增字段：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已覆盖 | 主业务对话入口，临床安全裁决位于输入安全放行、宠物上下文加载、语义抽取和候选召回之后 |
| `POST /openai/v1/responses` | 已覆盖 | OpenAI Responses 风格兼容入口，与主业务入口使用同一临床安全裁决语义 |

临床安全裁决不改变入口请求字段。调用方仍通过既有 `input`、`scope_assertion`、`vet_context`、`attachments`、`metadata` 和 `turn_options` 提交请求。

### 5.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次临床安全裁决迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 继续作为语义抽取和候选召回输入；OPA 不直接读取或扫描 |
| `scope_assertion.profile` | 继续作为服务端可信宠物画像来源；可间接进入结构化语义和策略输入 |
| `vet_context.pet_info` | 继续作为未验证资料兼容字段；不得覆盖可信画像参与硬裁决 |
| `attachments` | 继续由基础输入安全处理能力边界；临床安全裁决不解析附件内容 |
| `metadata` | 继续作为审计透传字段；不得作为临床策略规则来源 |
| `model` | 继续影响模型调用选择，不改变裁决契约 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |

后续如需调用方显式传入结构化临床事实，应通过独立接口契约评审，不应复用 `metadata` 或未验证 `vet_context.pet_info` 作为隐式权威来源。

### 5.3 稳定的响应可观察字段

临床安全裁决通过响应 metadata 和安全信号对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.clinical_safety_resolution` | 本轮临床安全链路总摘要 |
| `metadata.clinical_safety_resolution.policy_decision` | OPA 临床安全策略动作、原因、信号和策略后端摘要 |
| `metadata.clinical_safety_resolution.fallback_state.semantic` | 本轮语义抽取状态 |
| `metadata.clinical_safety_resolution.fallback_state.retrieval` | 本轮候选召回状态 |
| `metadata.clinical_safety_semantic` | 本轮结构化临床安全语义摘要 |
| `metadata.input_safety_decision` | 临床安全链路前置输入安全裁决摘要 |
| `metadata.multi_agent_path` | 应包含 `ClinicalSafetyPolicyOPA`，不得退化为裸 `OPA` |
| `safety_signals` | 可包含临床安全 OPA 策略返回并经主链路合并后的安全信号 |
| `status=safety_escalated` | 临床安全策略触发安全分诊响应 |
| `status=blocked` | 临床安全策略或基础输入安全策略阻断主链路 |

后续模块应依赖这些稳定字段进行跨领域对齐，不应依赖内部类名、Rego 规则体、测试替身、调用栈或 OPA 原始 HTTP 响应。

## 6. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收用户原文、可信范围声明、未验证宠物资料审计副本和幂等键 |
| 范围授权与 turn lock | 确定可信用户、宠物、会话范围，并进入统一回合执行边界 |
| 基础输入安全 | 先裁决输入完整性、附件能力边界和提示注入等非临床输入风险 |
| 宠物上下文加载 | 只加载服务端可信宠物画像，不用请求侧 pet_info 覆盖 |
| 临床安全语义抽取 | 输出结构化语义或明确低置信、失败状态 |
| 临床安全候选召回 | 使用 pgvector 从已审核临床安全 chunk 中召回候选 |
| 临床安全裁决输入组装 | 汇总候选、语义、召回状态、可信范围和阈值 |
| OPA 临床安全裁决 | 输出 allow、observe、escalate 或 block，并返回原因和安全信号 |
| 主链路分支 | 如触发安全升级或阻断则生成安全响应；否则继续问诊、RAG、回复生成和记忆写入 |
| 响应审计 | 写入策略动作、策略路径、信号、语义状态、召回状态和多 Agent 路径 |

后续领域模块应把临床安全裁决视为“临床安全候选进入主业务分支前的统一策略动作边界”，不是候选召回器、语义抽取器、问诊状态机或医学 RAG 引擎。

## 7. 降级与 Fail Fast 规则

临床安全裁决迁移后的核心原则是：策略不可用或策略结果不合法时，不启用本地硬编码裁决回退。

允许的降级：

1. 语义抽取低置信、失败、禁用或不可用时，将 `semantic.trusted=false` 传入策略，并保留显式语义状态。
2. pgvector 召回不可用、空命中或低质量时，将召回状态写入 metadata，不伪造候选。
3. 候选分数低于策略阈值时，OPA 可返回 `allow` 或 `observe`。
4. 可信语义明确否认暴露、远期既往已恢复或上下文不适用时，OPA 可抑制对应候选。
5. 测试或特殊嵌入场景可以显式注入策略客户端替身，但生产容器默认使用 OPA。

不允许的降级：

1. 不允许 OPA 不可用时回退 Python 关键词裁决。
2. 不允许 OPA 返回非法结构时宽松修复并继续执行。
3. 不允许在无候选时根据原始文本、语义字段或静态资产补造候选。
4. 不允许在 `semantic.trusted=false` 时使用否定、时间或暴露状态做抑制。
5. 不允许把 `retrieval.degraded=true` 当作启用文件短语兜底的理由。
6. 不允许让开发样例 JSON、seed 文件或静态资产决定生产安全动作。

Fail Fast 的含义不是所有临床安全不确定场景都阻断用户回答，而是裁决链路不能把不可信输入、不可用策略或非法响应包装成可信动作。系统可以继续透出明确失败或降级状态，但不能悄悄走另一套本地裁决可信源。

## 8. 配置与运行边界

当前临床安全裁决相关配置保持有限集合：

| 配置 | 当前语义 | 边界说明 |
|---|---|---|
| `CLINICAL_SAFETY_OPA_BASE_URL` | 临床安全 OPA Data API 基础地址 | 未配置时兼容复用 `INPUT_SAFETY_OPA_BASE_URL` |
| `CLINICAL_SAFETY_OPA_PACKAGE_PATH` | 临床安全 OPA package 路径 | 默认 `vet_agent.clinical_safety` |
| `CLINICAL_SAFETY_OPA_RULE_NAME` | 临床安全 OPA 决策规则 | 默认 `decision` |
| `CLINICAL_SAFETY_OPA_AUTH_TOKEN` | 临床安全 OPA 鉴权令牌 | 未配置时兼容复用输入安全 OPA token |
| `CLINICAL_SAFETY_VECTOR_MIN_SCORE` | 临床安全向量召回最低分数 | 属于召回阈值，不等同于策略动作阈值 |
| `LITELLM_BASE_URL` | LiteLLM OpenAI 兼容接口地址 | 用于语义抽取和 embedding，不由 OPA 访问 |
| `LITELLM_API_KEY` | LiteLLM API 密钥 | 敏感参数通过 env 或 GitHub Environment 注入 |
| `DATABASE_URL` | PostgreSQL 连接地址 | 生产候选召回依赖 PostgreSQL/pgvector |

当前兼容策略：

1. 临床安全 OPA 地址可复用输入安全 OPA 地址，以适配同一 OPA 实例承载多个 policy package 的部署方式。
2. 临床安全 OPA token 可复用输入安全 OPA token，以适配统一网关鉴权。
3. `metadata.multi_agent_path` 使用 `ClinicalSafetyPolicyOPA` 区分临床安全策略，不再使用裸 `OPA`。
4. 真实集成测试使用专用 `clinical-safety-api` try-run scope，不再把 Mem0 或普通问诊完整链路纳入当前门禁。

## 10. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不把 OPA 改造成临床文本解析器。
2. 不让 OPA 直接访问数据库、Mem0、RAG 或模型服务。
3. 不在 OPA 中维护关键词、正则、同义词或拼音匹配。
4. 不在 Python 中保留生产级本地硬编码裁决回退。
5. 不把临床安全裁决替代候选召回、语义抽取、问诊状态机或 RAG。
6. 不把开发样例 JSON、seed 文件或静态资产作为生产安全动作可信源。
7. 不把 `observe` 解释为临床无风险，只表示策略允许继续普通问诊。
8. 不把 `escalate` 解释为诊断结论，只表示需要优先线下处理的安全分诊动作。
9. 不把 `block` 作为普通临床急症默认动作；阻断语义需独立评审。
10. 不让真实外部 API 集成测试承担 Mem0、普通问诊完整链路或输入安全阻断的验收职责。

## 11. 后续实现对齐原则

后续迁移 RAG、记忆、输出安全、报告解析和管理后台时，应遵循以下约束：

1. 临床安全裁决只消费结构化候选和可信语义，不扫描原始文本。
2. 新增候选来源前，应先定义来源可信等级、候选编码、分数、审计字段和降级语义。
3. 新增策略字段前，应先定义字段来源、可信状态、未知值、低置信处理和 metadata 兼容方式。
4. 新增动作前，应明确调用方行为、响应状态、安全信号严重级别和回滚策略。
5. OPA 策略测试应覆盖动作矩阵和非法组合，API 集成测试只覆盖真实服务纵向主路径。
6. 临床安全外部集成测试应保持专用边界，不混入 Mem0、普通问诊完整链路或输入安全阻断测试。
7. RAG 医学知识不得替代临床安全候选或裁决。
8. Mem0 语义记忆不得作为临床安全候选的唯一依据。
9. 问诊状态机不得根据临床安全策略内部原因重写临床安全动作。
10. 输出安全复核可以补充用户响应约束，但不得覆盖临床安全 OPA 已做出的升级或阻断动作。

## 12. 验收基线

当前阶段后续修改不应破坏以下基线：

1. 临床安全裁决生产主路径使用 OPA。
2. OPA 只消费结构化候选、可信语义、召回状态、阈值和请求范围摘要。
3. OPA 不扫描原始文本，不生成候选，不执行医学诊断推理。
4. OPA 不可用或返回非法结果时，不启用本地硬编码裁决回退。
5. `semantic.trusted=false` 时，不使用否定、时间或暴露状态抑制候选。
6. 无候选时，OPA 不自行创建临床安全信号。
7. `metadata.clinical_safety_resolution.policy_decision.policy_backend=opa` 可观察。
8. `metadata.clinical_safety_resolution.policy_decision.policy_path=vet_agent.clinical_safety/decision` 可观察。
9. `metadata.multi_agent_path` 使用 `ClinicalSafetyPolicyOPA` 命名。
10. 临床安全升级响应继续透出前置 `input_safety_decision`。
11. 默认快速 CI 不要求真实外部服务，临床安全真实 API 测试需显式通过 `clinical-safety-api` scope 运行。
12. 临床安全真实 API 测试只覆盖 LiteLLM、PostgreSQL/pgvector 和 OPA 组成的本阶段纵向链路。
