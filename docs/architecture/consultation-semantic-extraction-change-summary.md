# 问诊语义抽取变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：问诊语义抽取、核心问诊事实、开放式结构化观察、当前会话工作记忆、问诊状态合并输入、响应 metadata 审计
>
> **不适用范围**：临床安全裁决、RAG 知识证据、自然语言回复生成、长期记忆候选抽取、长期事实写入、管理后台资产治理和前端展示编排

## 1. 变更目的

本次迁移将问诊语义抽取从旧版手写 JSON 解析、关键词/正则补槽和固定槽位漏斗中收束出来，改为以 LiteLLM `response_format`、Pydantic 契约、核心事实与开放观察并行输出作为主路径。

迁移前，问诊语义链路存在以下风险：

1. 模型输出依赖提示词要求“只输出 JSON”，业务代码仍需要宽松解析或兼容修复。
2. 问诊状态层存在关键词、正则或短语匹配路径，容易把本轮输入误读为结构化事实。
3. `ConsultationFactKey` 容易被误解为兽医问诊事实全集，导致核心槽位不断扩张。
4. 枚举外事实只能被塞入 `symptom_detail`，或在状态合并中丢失。
5. 用户明确要求先回答时，系统可能继续按固定槽位缺失机械追问。
6. 问诊语义、问诊状态、长期记忆写入和临床安全动作边界不够清晰。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 用户本轮输入 | 原始陈述 | 多任务拆分之后 | 作为问诊语义抽取的自然语言来源 |
| 可信宠物画像摘要 | 服务端可信上下文 | 宠物上下文加载之后 | 辅助理解身份、物种、年龄、体重等上下文 |
| 核心问诊事实 `facts` | 可信结构化事实 | 问诊语义抽取结果 | 进入当前会话工作记忆，并派生兼容 `slots` 视图 |
| 开放式结构化观察 `observations` | 可信结构化观察 | 问诊语义抽取结果 | 进入当前会话工作记忆和证据画像，不直接驱动固定槽位状态机 |
| 用户意图 `intent` | 可信意图信号 | 问诊语义抽取结果 | 供回答充分性策略判断回答范围和追问必要性 |
| 语义状态 `strategy` | 可审计运行状态 | 响应 metadata | 表示本轮问诊语义是否可信、低置信、禁用、不可用、失败或 schema 非法 |

问诊语义抽取只回答“用户本轮输入和可信宠物画像中可被结构化表达的问诊事实、开放观察和意图信号是什么”。它不负责更新长期记忆，不负责临床安全动作裁决，不负责生成追问，也不负责生成最终答复。

## 2. 职责边界

### 2.1 语义抽取层职责

问诊语义抽取层当前负责：

1. 使用 LiteLLM `response_format` 执行结构化输出约束。
2. 使用 Pydantic 契约校验字段、枚举边界、置信度范围和开放观察结构。
3. 输出核心问诊事实、开放观察、用户意图、整体置信度、策略状态和失败原因。
4. 在低置信、禁用、不可用、调用失败或 schema 非法时返回明确失败状态。
5. 区分核心槽位事实与枚举外开放观察，避免为了覆盖所有表达而扩张核心槽位。
6. 将结构化结果写入 `metadata.semantic_extraction`，供审计和后续排障使用。

问诊语义抽取层不负责：

1. 使用关键词、正则、静态 seed 或手写 JSON 修复路径补造问诊事实。
2. 把诊断名、疾病名、治疗方案、用药方案或安全动作写入问诊事实。
3. 根据开放观察直接决定追问、急诊、阻断、升级或长期写入。
4. 更新 `consultation_states` 之外的长期事实、宠物资料或 Mem0 语义投影。
5. 读取 RAG 知识库、临床安全资产或长期记忆作为事实权威来源。
6. 在模型不可用或低置信时启用本地规则兜底。

### 2.2 核心事实职责

核心问诊事实 `facts` 用于表达当前问诊状态层可稳定消费的少量事实维度。

核心事实当前表达：

1. 宠物身份相关事实，如物种、年龄阶段或年龄、体重。
2. 主诉时间相关事实，如起病时间。
3. 全身状态相关事实，如精神状态、食欲饮水。
4. 常见问诊域相关事实，如呕吐、大便、呼吸、疼痛或活动、行为场景、当前饮食。
5. 必要时的症状补充摘要。

核心事实不表达：

1. 所有可能的兽医医学观察。
2. 医学本体、疾病分类或诊断结论。
3. 长期记忆 fact type 或 fact key。
4. 临床安全动作。
5. RAG 检索标签。
6. 前端展示模板。

`ConsultationFactKey` 的定位是“当前会话问诊状态可消费的核心槽位契约”，不是“兽医问诊事实全集”。新增核心事实键必须经过业务评审，并同步更新语义契约、状态合并、目录 seed、数据库迁移、测试和本文档。

### 2.3 开放观察职责

开放式结构化观察 `observations` 用于保留用户明确表达但无法自然归入核心槽位的事实。

开放观察可以表达：

1. 排尿、生殖、皮肤、耳朵、眼部、口腔、神经、外伤、环境、接触史等非核心槽位观察。
2. 用户明确否认的非核心观察。
3. 用户表达不确定但仍有审计价值的观察。
4. 与当前主诉相关但暂不适合进入长期事实的临时问诊信息。
5. 开放观察类别、中文标签、归一值、确认状态、来源原文、时间原文和置信度。

开放观察不表达：

1. 系统必须执行的业务动作。
2. 疾病诊断结论。
3. 长期记忆写入命令。
4. 宠物资料覆盖命令。
5. 临床安全最终裁决。
6. 固定追问状态机条件。

开放观察进入当前会话工作记忆和证据画像。下游可以在提示词上下文、回答范围说明或后续策略输入中消费它，但不得因为存在某个开放观察类别就直接触发硬编码动作。

### 2.4 用户意图职责

用户意图 `intent` 只表达本轮输入中的控制信号，不直接替代策略执行。

当前稳定意图包括：

| 字段 | 语义 | 允许用途 |
|---|---|---|
| `answer_now` | 用户明确要求根据现有信息先回答、别继续追问或先给阶段性判断 | 回答充分性策略应尽量给范围性回答，而不是机械追问 |
| `wants_triage` | 用户明确询问严重程度、是否急诊或是否需要线下检查 | 可作为回答范围和风险提示强度输入 |
| `correction` | 用户明确纠正当前会话事实 | 问诊状态合并可在当前会话范围内处理事实替换 |
| `raw_intent` | 用户意图简短审计摘要 | 仅用于 metadata 和排障 |

当前业务要求下，`answer_now=true` 时应尽量根据已有信息输出阶段性、范围性回答。信息不足时，回复应说明不确定边界和需要补充的信息，而不是由系统自身机械决定继续追问。

`correction=true` 只表示用户提出当前会话范围内的纠正语境。是否写入长期事实、是否覆盖服务端可信宠物资料、是否同步删除语义投影，均属于后续长期事实治理或删除纠正治理范围。

## 3. 数据链位置

问诊语义抽取位于当前 Agent 主数据链的固定位置：

```text
基础输入安全
-> 宠物上下文加载
-> 临床安全语义抽取
-> 临床安全候选召回
-> 临床安全裁决
-> 记忆读取
-> 多任务拆分
-> 问诊语义抽取
-> 问诊状态合并
-> 回答充分性策略
-> 追问 RAG 或回答 RAG
-> 回复生成
-> 输出安全复核
-> 长期记忆候选抽取
-> 长期事实写入
-> 回合留痕
```

该顺序的含义是：

1. 问诊语义抽取不会绕过输入安全、身份范围、临床安全裁决、记忆读取和多任务拆分。
2. 问诊语义抽取只消费当前任务文本、可信宠物画像摘要和上一轮当前会话状态。
3. 问诊语义结果进入问诊状态合并，不直接进入长期事实写入。
4. 多任务场景下，每个任务应拥有独立问诊语义抽取和状态合并结果。
5. 问诊语义失败时，本轮不应启用关键词、正则或 seed 回退补造事实。

## 4. 接口兼容边界

### 4.1 已覆盖的主业务入口

以下入口继续使用既有请求结构，不要求调用方新增问诊语义字段：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已覆盖 | 主业务对话入口，问诊语义抽取在多任务拆分之后执行 |
| `POST /openai/v1/responses` | 已覆盖 | OpenAI Responses 风格兼容入口，与主业务入口使用同一问诊语义链路 |

调用方仍按既有契约提交 `input`、`scope_assertion`、`vet_context`、`attachments`、`metadata`、`turn_options` 和 `stream`。问诊语义抽取不要求调用方预先声明核心槽位、开放观察或意图。

### 4.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次问诊语义抽取迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 继续作为用户本轮原文来源；多任务路径中使用当前任务文本 |
| `scope_assertion` | 继续作为可信用户、宠物和会话范围来源 |
| `vet_context.pet_info` | 继续作为未验证宠物资料兼容字段，不得覆盖服务端可信宠物画像 |
| `attachments` | 继续由输入安全、报告解析或后续能力边界处理，问诊语义抽取不解析附件内容 |
| `metadata` | 继续作为审计透传字段，不得作为问诊事实硬规则来源 |
| `model` | 继续影响模型选择，不改变问诊语义输出契约 |
| `turn_options.max_followup_questions` | 继续由问诊状态和追问规划使用 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |

后续如果需要调用方显式传入结构化问诊事实，应通过独立接口契约评审，不应复用 `metadata` 或未验证 `vet_context.pet_info` 作为隐式事实来源。

### 4.3 稳定的响应可观察字段

问诊语义抽取通过响应 metadata 和问诊状态摘要对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.semantic_extraction` | 本轮问诊语义抽取摘要 |
| `metadata.semantic_extraction.strategy` | 结构化语义策略或失败状态 |
| `metadata.semantic_extraction.trusted` | 本轮语义结果是否可进入问诊状态合并 |
| `metadata.semantic_extraction.facts` | 通过契约校验的核心问诊事实 |
| `metadata.semantic_extraction.observations` | 通过契约校验的开放式结构化观察 |
| `metadata.semantic_extraction.intent` | 用户意图信号 |
| `metadata.semantic_extraction.applied_fact_keys` | 本轮实际派生到核心槽位视图的事实 key |
| `metadata.semantic_extraction.applied_observation_count` | 本轮进入当前会话工作记忆的开放观察数量 |
| `metadata.semantic_extraction.used_as_primary_semantic_path` | 是否有可信语义进入本轮问诊状态 |
| `metadata.consultation_state.slots` | 兼容既有提示词和响应的核心槽位派生视图 |
| `metadata.consultation_state.working_facts` | 当前会话范围内的核心事实工作记忆 |
| `metadata.consultation_state.observations` | 当前会话范围内的开放观察工作记忆 |
| `metadata.consultation_state.evidence_profile.open_observations` | 开放观察对回答充分性证据画像的摘要 |

后续模块可以依赖上述字段进行领域对齐和排障，但不应依赖内部类名、提示词正文、模型原始响应、测试替身或调用栈细节。

### 4.4 兼容保留的旧视图

`consultation_state.slots` 继续保留，作为既有回复生成、追问 RAG、reasoning display 和部分测试的兼容视图。

该视图的稳定语义是：

1. `slots` 是从可信核心事实和服务端可信宠物画像中派生出的紧凑视图。
2. `slots` 不是完整事实源。
3. `slots` 不承载开放观察。
4. `slots` 不直接表示长期记忆事实。
5. `slots` 不应被扩张为完整医学状态机。

后续新能力应优先消费 `working_facts`、`observations` 和 `evidence_profile`，而不是继续把所有信息压入 `slots`。

## 5. 状态合并边界

问诊状态合并位于问诊语义抽取之后，负责把可信结构化结果写入当前会话状态。

状态合并当前负责：

1. 恢复上一轮当前会话状态。
2. 从服务端可信宠物画像预填稳定身份信息。
3. 合并可信核心事实到当前会话工作记忆。
4. 从核心事实派生兼容 `slots` 视图。
5. 合并开放观察到当前会话工作记忆。
6. 构建回答充分性需要的证据画像。
7. 保留本轮语义抽取 metadata。

状态合并不负责：

1. 重新读取用户原文执行关键词或正则解析。
2. 在问诊语义失败时补造结构化事实。
3. 根据开放观察直接生成业务动作。
4. 写入长期事实、Mem0 语义投影或宠物资料。
5. 替代临床安全裁决。
6. 替代最终回复生成。

状态合并应被理解为“当前会话工作记忆维护层”，不是长期记忆层，也不是自定义规则状态机。

## 6. 与其他领域的边界

### 6.1 与临床安全语义抽取的边界

问诊语义抽取和临床安全语义抽取属于不同阶段。

| 领域 | 主要问题 | 输出用途 |
|---|---|---|
| 临床安全语义抽取 | 本轮输入是否包含临床安全相关结构化语义 | 增强临床安全候选召回和裁决前输入 |
| 问诊语义抽取 | 本轮输入中有哪些问诊事实、观察和意图 | 更新当前会话问诊状态和回答充分性证据 |

问诊语义抽取不得输出临床安全最终动作；临床安全语义抽取也不得代替问诊状态合并。

### 6.2 与多任务拆分的边界

多任务拆分先于问诊语义抽取执行。问诊语义抽取只处理任务执行计划中的当前任务文本。

多任务拆分负责“本轮输入是否包含多个任务”；问诊语义抽取负责“当前任务文本中有哪些问诊事实、观察和意图”。二者不得互相回退。

### 6.3 与回答充分性策略的边界

问诊语义抽取只提供结构化输入。是否回答、如何限定回答范围、是否追问和追问哪些高价值信息，由回答充分性策略决定。

当前业务要求下，`answer_now=true` 时回答充分性策略应尽量允许阶段性回答。信息不足时，应生成范围性回答和不确定边界，而不是机械阻塞为追问。

### 6.4 与 RAG 的边界

问诊语义结果可作为 RAG 查询上下文的一部分，但不是医学知识证据。

RAG 仍应从知识库或已审核医学资产中召回证据。问诊语义中的 `facts` 和 `observations` 只能说明用户说了什么，不能说明医学上一定成立什么。

### 6.5 与长期记忆的边界

问诊语义结果不直接写入长期记忆。

长期记忆候选抽取和长期事实写入应单独执行：

1. 长期记忆候选抽取可参考本轮输入、当前回复、当前会话状态和开放观察。
2. 长期事实写入必须经过主体范围、事实类型、确认状态、冲突和纠正策略裁决。
3. 开放观察不能绕过长期事实治理直接写入 `pet_memory_facts`。
4. Mem0 只作为语义投影，不替代 PostgreSQL 权威事实库。

## 7. 目录与静态资产边界

`consultation_domains` 和 `consultation_slots` 的定位是问诊目录，而不是抽取规则库。

目录当前允许表达：

| 目录 | 允许表达 |
|---|---|
| `consultation_domains` | 问诊领域稳定标识、建议关注的核心槽位、排序、启用状态和版本 |
| `consultation_slots` | 核心槽位稳定标识、中文标签、默认追问文案、排序、启用状态和版本 |

目录不允许表达：

1. 关键词、正则、同义词或示例句抽取规则。
2. 临床安全动作。
3. 长期记忆写入策略。
4. RAG 检索规则。
5. 开放观察类别全集。
6. 模型失败后的兜底事实生成规则。

仓库 seed 只用于开发初始化和迁移参考，不是生产语义事实的可信源。生产目录应来自数据库中的已发布配置。

## 8. 显式失败语义

问诊语义抽取失败时，系统必须暴露明确状态，不允许静默回退为规则抽取。

当前稳定策略状态包括：

| 状态 | 语义 | 允许用途 |
|---|---|---|
| `litellm_response_format` | 结构化输出通过 Pydantic 校验且达到置信度阈值 | 可进入问诊状态合并 |
| `litellm_response_format_low_confidence` | 结构化输出通过校验但整体置信度低于阈值 | 只进入 metadata，不进入状态合并 |
| `semantic_extraction_disabled` | 当前环境显式关闭问诊语义抽取 | 只进入 metadata |
| `semantic_extraction_unavailable` | 结构化模型客户端不可用 | 只进入 metadata |
| `semantic_extraction_failed` | 模型调用或结构化调用失败 | 只进入 metadata |
| `semantic_extraction_invalid_schema` | 模型返回不符合结构化契约 | 只进入 metadata |
| `skipped` | 本轮未执行或未传入语义结果 | 只作为默认未执行状态 |

低置信、失败、禁用、不可用或 schema 非法时，下游可继续基于用户原文生成谨慎回复或追问，但不得把规则猜测结果伪装成可信问诊事实。

## 10. 明确不做事项

为了保持问诊语义抽取边界清晰，以下事项不属于当前阶段：

1. 不把 `ConsultationFactKey` 扩张为完整兽医医学本体。
2. 不把开放观察类别扩张为新的硬规则状态机。
3. 不恢复关键词、正则、静态 seed 或手写 JSON 修复路径。
4. 不在语义抽取失败时生成猜测型问诊事实。
5. 不让未验证 `vet_context.pet_info` 覆盖服务端可信宠物画像。
6. 不把问诊语义结果直接写入长期记忆事实。
7. 不把问诊语义结果作为 RAG 医学知识证据。
8. 不让 OPA 或策略层扫描原始文本补造问诊事实。
9. 不把 `observations` 直接映射为临床安全动作。
10. 不把活跃问诊状态迁入 Mem0。

## 11. 后续实现对齐原则

后续迁移问诊状态、追问 RAG、回答 RAG、回复生成、长期记忆候选和长期事实写入时，应遵守以下原则：

1. 以 `metadata.semantic_extraction.strategy` 和 `trusted` 判断语义可信状态。
2. 以 `facts` 表达核心槽位事实，以 `observations` 表达枚举外观察。
3. 以 `working_facts` 和 `observations` 作为当前会话工作记忆输入。
4. 以 `slots` 作为兼容视图，不作为完整事实源。
5. 以 `evidence_profile` 作为回答充分性和追问规划的主要结构化输入。
6. 用户 `answer_now=true` 时，应尽量输出阶段性、范围性回答。
7. 长期记忆写入必须经过独立候选抽取和策略裁决。
8. 新增核心槽位必须经过契约、目录、测试和文档同步；不能仅修改静态 seed。
9. 新增开放观察类别不应要求同步新增代码分支，除非它已经成为稳定业务策略输入。
10. 任何模型失败、低置信或 schema 非法场景都应 Fail Fast 并保留可审计原因。

## 12. 验收基线

后续改动至少应保持以下验收基线：

1. 结构化问诊语义抽取通过 LiteLLM `response_format` 和 Pydantic 契约返回。
2. 低置信、禁用、不可用、调用失败和 schema 非法均返回显式状态。
3. 核心槽位事实可以继续派生到 `consultation_state.slots`。
4. 枚举外观察可以进入 `consultation_state.observations`，且不进入核心 `slots`。
5. `metadata.semantic_extraction.observations` 对外可审计。
6. `answer_now=true` 不被固定槽位缺失机械阻塞。
7. 静态 seed、数据库目录和状态合并层不恢复关键词或正则抽取规则。
8. 全量测试应覆盖核心事实路径、开放观察路径、低置信路径和 schema 失败路径。
