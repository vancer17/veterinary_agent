# 回复生成上下文编译变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：回答充分性 `answer` 分支、回复生成上下文编译、LiteLLM/Qwen 调用、响应审计和输出安全前置边界
>
> **不适用范围**：输入安全裁决、临床安全语义抽取、临床安全动作裁决、任务路由、问诊状态与回答充分性裁决、RAG 检索、事实冲突治理、长期记忆写入、输出安全最终裁决

## 1. 变更目的

本次迁移将旧版回复合成链路中的提示词拼装、问诊状态格式化、模型调用、输出清洗和硬编码回复回退拆分为明确的数据链边界。

迁移后的回复生成链路只负责：

1. 接收已经完成上游处理的结构化结果。
2. 将结构化结果按照固定顺序编译为模型上下文。
3. 调用 LiteLLM/Qwen 兼容模型生成自然语言回复。
4. 输出模型原始结果和回复生成审计摘要。

该阶段不新增语义理解能力，不重新建立关键词规则、问诊状态机或临床安全裁决器。

## 2. 数据链位置

回复生成上下文编译位于问诊回答充分性和回答相关 RAG 之后、模型生成与输出安全处理之前。

```text
身份、宠物资料与会话范围
-> 基础输入安全
-> 临床安全语义与裁决
-> 记忆读取
-> 多任务拆分
-> 问诊语义抽取
-> 问诊状态与回答充分性
-> 追问 RAG 或回答 RAG
-> 回复生成上下文编译
-> Qwen 兼容模型生成
-> 输出清洗
-> 输出安全复核
-> 长期记忆候选抽取与写入
-> 留痕与响应终态
```

只有当前任务已经进入回答充分性 `answer` 分支时，才允许进入回复生成上下文编译。

`ask`、`escalate`、`block` 或其他非回答分支不得通过回复生成上下文编译器生成普通问诊回复。

## 3. 作用边界

### 3.1 允许承担的职责

回复生成上下文编译允许承担以下职责：

1. 按固定顺序组织系统约束、策略摘要、问诊状态、记忆和回答证据。
2. 将上游结构化字段转换为模型可读文本。
3. 对已经确定的模型可见字段进行字符裁剪和长度预算控制。
4. 保持任务级、会话级和宠物级上下文的显式范围标识。
5. 将模型调用所需消息和审计 metadata 组装为稳定结果。
6. 对输入对象执行必要的契约检查，发现关键结构缺失时直接失败。

### 3.2 明确不承担的职责

回复生成上下文编译不得承担以下职责：

1. 从用户文本重新识别症状、意图、风险或任务。
2. 通过关键词、正则、默认值或固定短语决定回答结论。
3. 重新决定本轮应回答还是应追问。
4. 修改问诊状态、任务路由或回答充分性结果。
5. 重新裁决临床安全动作或覆盖 OPA 结果。
6. 将历史记忆提升为当前任务事实。
7. 解决权威事实、会话事实和语义记忆之间的冲突。
8. 执行事实删除、纠正、禁用或长期记忆治理。
9. 在模型调用失败时生成硬编码回复。
10. 对模型输出执行最终清洗或安全复核。

事实冲突、删除和纠正治理继续由独立治理链路负责，不应下沉到回复生成阶段。

## 4. 稳定输入边界

回复生成阶段只消费以下上游结构化结果：

| 输入 | 数据链角色 | 回复生成阶段用途 |
|---|---|---|
| `RoutedTask` | 已完成任务路由的当前任务 | 提供当前任务文本、任务域和展示标题 |
| `ClinicalSafetySemanticResult` | 临床安全语义结果 | 提供必要的安全语义摘要和降级状态 |
| `ClinicalSafetyEvaluationResult` | 临床安全策略结果 | 解释和呈现上游安全动作，不重新裁决 |
| `ConsultationDecision` | 当前任务问诊状态与回答充分性结果 | 提供当前任务事实和已完成的回答分支结果 |
| `PetContext` | 服务端范围授权后的宠物上下文 | 提供已验证宠物资料和可展示证据 |
| `MemoryPromptContext` | 已分层的记忆读取结果 | 提供受范围和可信等级约束的历史参考 |
| `AnswerRagResult` | 已审核的回答相关证据 | 提供当前回答允许使用的知识依据 |

上述对象的生产来源、事实可信度和策略语义由上游领域负责。回复生成阶段不得根据对象内容再次推断其业务含义。

## 5. 模型可见数据边界

### 5.1 允许进入模型上下文的内容

模型可以看到以下内容：

1. 当前任务文本。
2. 当前任务的稳定展示元数据。
3. 上游临床安全裁决的模型可见摘要。
4. 上游回答充分性结果，包括回答范围和未确认边界。
5. 服务端已验证的宠物基础资料。
6. 当前任务的结构化问诊事实和观察摘要。
7. 按范围和可信等级过滤后的历史记忆。
8. 已审核回答相关 RAG 的标题、摘要和来源标签。
9. 固定的回复格式约束。

当前用户任务文本不会被移除。它是回复生成的必要输入，但必须被视为用户数据，而不是系统指令或权威事实。

### 5.2 不应进入模型提示词的内部字段

以下字段默认只用于审计、排障或链路追踪，不属于模型可见业务内容：

1. `user_id`、`pet_id`、`session_id`。
2. `task_id`、`task_key` 和内部任务引用。
3. `request_id`、`trace_id`。
4. 原始策略 `policy_payload`。
5. 语义抽取置信度、检索分数和内部 evidence ID。
6. 原始语义抽取文本和内部调试字段。
7. 数据库模型字段、内部状态字段和仓储实现信息。

响应 metadata 是否向外部调用方暴露上述审计字段，应由 API 可见性契约另行规定，不应与模型提示词可见性混淆。

## 6. 上下文分区顺序

模型上下文保持以下稳定顺序：

1. 当前回合系统生成约束。
2. 临床安全裁决与必要语义摘要。
3. 当前任务回答充分性结果。
4. 服务端已验证宠物资料。
5. 当前任务结构化问诊状态。
6. 分层记忆上下文。
7. 回答相关 RAG 证据。
8. 当前用户任务文本。
9. 回复输出格式约束。

该顺序表达数据可信边界，不表示回复生成器可以对不同来源进行重新裁决。

## 7. 记忆上下文边界

记忆上下文只作为历史参考，不是当前回合的事实裁决来源。

当前允许的记忆范围如下：

| 范围 | 可信等级 | 允许用途 |
|---|---|---|
| `pet` | `authoritative` | 提供 PostgreSQL 权威长期事实 |
| `pet` | `episode` | 提供宠物历史事件摘要 |
| `pet` | `semantic_hint` | 提供 Mem0 语义历史线索 |
| `session_shared` | `conversational` | 提供当前会话共享参考 |
| `task` | 结构化可信等级 | 仅在 `task_key` 与当前任务明确匹配时使用 |

记忆处理必须遵守以下原则：

1. 不根据标题、症状、关键词或向量相似度猜测任务归属。
2. 没有明确任务键的历史数据不得强行归入某个任务。
3. Mem0 语义线索不得覆盖当前任务结构化事实。
4. Mem0 语义线索不得覆盖服务端已验证宠物资料。
5. Mem0 语义线索不得覆盖 PostgreSQL 权威长期事实。
6. 记忆层不负责解决事实冲突，冲突应进入独立治理链路。

## 8. Fail Fast 契约

回复生成上下文编译和模型调用不提供硬编码回复回退。

以下情况必须显式失败：

1. 当前任务文本为空。
2. `ConsultationDecision.ready` 不是 `True`。
3. `answerability.decision` 不是 `answer`。
4. 回答相关 RAG 没有有效知识命中。
5. RAG 命中缺少标题、摘要或来源。
6. 上游结构化字段缺失、类型不合法或范围不一致。
7. 固定系统约束和输出格式无法放入当前字符预算。
8. LiteLLM/Qwen 客户端未配置或不可用。
9. 模型调用失败。
10. 模型返回结果不满足最小输出契约。

不允许重新引入以下回退路径：

1. 默认回复模板。
2. 关键词或正则回复路径。
3. 开发样例 JSON 回复路径。
4. 静态 RAG 资产或本地文件知识回退。
5. 旧版 `ResponseComposer` 的内联兜底。
6. 模型不可用时切换到本地内存模型。

## 9. 兼容接口

### 9.1 外部主入口

本次迁移不新增回复生成专用 HTTP 入口，继续通过既有业务入口触发：

| 接口 | 兼容语义 |
|---|---|
| `POST /agent/turns` | 主业务对话入口 |
| `POST /openai/v1/responses` | OpenAI Responses 风格兼容入口 |

调用方不需要提交专用的回复生成上下文字段，也不应自行提交临床安全动作、回答充分性结果、记忆分区或 RAG 命中。

### 9.2 稳定结构化协议

以下协议作为后续实现和跨模块调用的稳定对齐面：

| 协议 | 语义 |
|---|---|
| `ResponseGenerationRequest` | 回复生成阶段唯一的结构化输入 |
| `ResponseGenerationContext` | 编译后的系统消息、用户消息和上下文审计摘要 |
| `ResponseGenerationResult` | 模型原始回复、上下文审计和进入生成阶段的证据 |
| `ResponseGenerationServiceProtocol` | 主编排器依赖的回复生成服务协议 |
| `metadata.response_generation` | 回复生成策略、上下文预算和输入审计摘要 |
| `metadata.multi_agent_path` | 当前回合执行路径摘要 |

后续实现可以调整包内组织方式，但不应破坏上述跨领域语义。

### 9.3 兼容行为

本次迁移保持以下行为：

1. 最终自然语言回复仍由 LiteLLM/Qwen 兼容模型生成。
2. 回复生成只发生在回答充分性 `answer` 分支。
3. 多任务场景仍按任务分别生成回答或追问。
4. 输出清洗和输出安全复核仍位于模型生成之后。
5. 宠物资料、记忆和回答 RAG 证据仍可进入最终响应证据链。
6. 外部响应主结构、主入口和流式响应协议保持兼容。

本次迁移新增或稳定化的可观察内容包括：

1. 回复生成策略标识。
2. 回复生成上下文编译审计节点。
3. 提示词字符预算和裁剪状态。
4. 回答充分性、回答 RAG 和临床安全裁决的摘要信息。

## 10. 多任务边界

多任务场景下，每个任务都必须使用自己的：

1. 任务文本。
2. 问诊状态。
3. 回答充分性结果。
4. 回答相关 RAG 结果。
5. 回复生成上下文。

宠物级和 `session_shared` 记忆可以作为多个任务的共享参考，但不得因此将一个任务的状态、回答证据或任务专属记忆复制到其他任务。

回复生成阶段只能使用上游已经确认的任务范围，不得重新拆分、重命名、合并或猜测任务。

## 11. 输出链路边界

回复生成服务只返回模型原始文本和生成审计结果，不负责完成最终用户输出治理。

后续链路继续负责：

1. 具体剂量清洗。
2. 绝对化诊断表述弱化。
3. 内部提示词和链路术语清理。
4. 输出安全信号聚合。
5. 输出安全策略复核。
6. 响应终态封存与长期记忆候选处理。

回复生成阶段不得为了“提前保证安全”而复制一套输出关键词状态机。

## 12. 有意保留的 TODO

以下事项是当前初版有意后置的工程项，不表示可以在回复生成阶段新增业务裁决逻辑：

| TODO | 当前处理方式 | 后续方向 |
|---|---|---|
| 模型可见字段严格正向白名单 | 先依赖上游结构化契约和稳定投影 | 建立运行时严格投影模型，拒绝未知或嵌套内部字段 |
| legacy `prompt_text` 兼容路径收束 | 保留有限兼容能力，生产主路径使用结构化 sections | 迁移完成后删除整体文本回退 |
| 宠物上下文细粒度投影 | 初版以已验证基础资料为主要回复上下文 | 为遥测、算法风险和告警建立独立可信投影 |
| token 级提示词预算 | 当前使用字符预算 | 根据实际模型 tokenizer 引入 token 预算 |
| 提示词版本化 | 通过策略标识和 metadata 记录当前生成策略 | 建立独立提示词版本和变更审计 |
| 多任务专属记忆 | 共享记忆保持显式范围标识 | 在来源阶段保存明确 `task_key` 并建立任务级记忆读取 |
| API metadata 可见性分层 | 保留现有审计摘要 | 区分终端用户、业务服务和运维审计字段 |
| Guardrails 输出约束 | 继续使用独立输出清洗与安全复核 | 以 observe 模式接入结构化输出检测，再评估 enforce |
| 多语言回复模板 | 当前以中文宠物问诊为主要范围 | 建立语言和地区级回复策略 |

上述 TODO 不得通过以下方式提前补齐：

1. 在回复生成阶段增加关键词或正则裁决。
2. 根据历史记忆自行解决事实冲突。
3. 根据问诊槽位自行决定是否追问。
4. 根据宠物算法风险自行升级临床动作。
5. 在模型不可用时启用静默回退。
6. 让 Mem0 语义线索覆盖权威事实。

## 13. 测试与验收边界

回复生成上下文编译应同时具备本地契约测试和显式真实服务集成测试。

测试只依赖稳定可观察行为，不固定断言 Qwen 的自然语言全文。

至少应验证：

1. `ask` 分支无法进入回复生成。
2. 无有效回答 RAG 命中时直接失败。
3. 上游临床安全动作和回答充分性结果被原样投影，不被编译器重判。
4. Mem0 只以语义历史线索进入记忆分区。
5. 不匹配的 task 记忆不会进入当前任务。
6. 回复生成位于回答 RAG 之后、输出安全复核之前。
7. 真实 LiteLLM/Qwen、OPA、PostgreSQL/pgvector 和可选 Mem0 的链路可以通过 SSH 隧道进行集成验证。
8. 真实服务失败时不会切换到本地内存模型或硬编码回复。

测试不依赖仓库内开发样例 JSON、静态 RAG 资产或不稳定的自然语言快照。

## 14. 后续对齐原则

后续涉及回复生成上下文编译的变更，统一遵守以下原则：

1. 先保持外部入口和稳定协议，再调整内部实现。
2. 回复生成阶段只消费上游结构化结果。
3. 不在本阶段恢复语义理解、状态机或策略裁决。
4. 不让历史记忆覆盖当前任务事实或权威宠物资料。
5. 不把内部标识、策略 payload、检索分数和原始审计文本作为模型业务上下文。
6. 依赖缺失、结构不合法和有效证据缺失时直接失败。
7. 所有新增字段必须明确其来源、可信等级、适用范围和模型可见性。
8. 事实冲突、删除、纠正和长期记忆治理继续由独立领域负责。
9. 本文档中的 TODO 不得通过自定义规则状态机提前实现。
