# 输出清洗与安全复核变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：回复生成后的统一出口复核、输出安全候选、策略裁决、审计路径和输出安全 metadata
>
> **不适用范围**：输入安全裁决、临床安全裁决、问诊状态机、RAG 检索、长期记忆写入、主业务请求契约重构

## 1. 变更目的

本次迁移的目标，是将旧版输出清洗与安全复核中的字符串修补、规则软化和回退模板收束为统一的输出安全边界，使输出侧从“手写改写文本”转为“结构化候选 + 策略裁决 + 最终出口复核”。

迁移后，输出安全链路只负责回答以下问题：

1. 当前响应是否存在需要策略关注的输出风险候选。
2. 这些候选应当如何被裁决为允许、观测、阻断、升级或后续改写。
3. 审计路径和响应 metadata 应如何记录该轮复核结果。

输出安全链路不负责重新生成回复，不负责重新建立问诊状态，也不负责把输出安全转回输入安全、临床安全或记忆治理逻辑。

## 2. 作用边界

### 2.1 允许承担的职责

输出安全复核允许承担以下职责：

1. 在回复生成完成后，对用户可见响应做统一出口复核。
2. 采集结构化输出候选，并交由策略层决定最终动作。
3. 将复核结果写入 `AgentTurnResponse` 的 `metadata` 与 `safety_signals`。
4. 在审计路径中记录输出安全节点，便于后续排障与门禁追踪。
5. 在显式启用时，允许观测模式与强制模式并存，以便分阶段加严。
6. 在候选、策略或运行模式缺失时采取明确的 fail-fast 语义，而不是回退旧补丁路径。

### 2.2 明确不承担的职责

输出安全复核不得承担以下职责：

1. 从原始用户输入重新识别临床意图。
2. 代替回复生成器完成自然语言组织。
3. 代替临床安全裁决器决定医疗动作。
4. 代替输入安全门禁判断请求是否允许进入主链路。
5. 以局部字符串替换方式对已生成文本做连续修补。
6. 以关键词状态机的方式重建业务规则。
7. 以默认文案回退的方式掩盖策略或依赖失败。
8. 在输出侧直接写入长期记忆事实。

### 2.3 与其它链路的边界

| 关联链路 | 当前边界 |
|---|---|
| 回复生成 | 输出安全位于回复生成之后，不参与上下文编译和模型调用 |
| 临床安全 | 输出安全只复核最终文本，不重新裁决临床动作 |
| 输入安全 | 输入安全处理请求进入主链路前的候选与动作，输出安全处理响应离开主链路前的候选与动作 |
| 记忆抽取 | 输出安全不决定记忆是否抽取；是否跳过由编排层在安全阻断后处理 |
| 留痕审计 | 输出安全只提供审计结果与节点，不接管留痕仓储 |

## 3. 兼容接口

### 3.1 外部 HTTP 接口

本次迁移不新增专用输出安全 HTTP 接口。既有主入口保持不变：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 兼容 | 主业务对话入口继续使用同一响应契约 |
| `POST /openai/v1/responses` | 兼容 | OpenAI Responses 风格入口继续使用同一响应契约 |

调用方不需要为输出安全复核新增专用请求字段，也不需要切换请求格式。

### 3.2 稳定响应面

输出安全复核通过以下稳定响应面向外暴露结果：

| 稳定面 | 语义 |
|---|---|
| `safety_signals` | 复核过程中形成的输出安全信号集合 |
| `metadata.output_safety_decision` | 本轮输出安全裁决摘要 |
| `metadata.multi_agent_path` | 统一审计路径中的输出安全节点 |
| `status` | 在强制模式下，仅在策略要求阻断或升级时改变终态 |
| `segments[].type` | 保持现有段落模型，不要求调用方适配新 payload 结构 |

其中，输出安全增加的是“可审计的决策结果”，不是新的用户交互协议。

### 3.3 稳定配置面

输出安全的行为通过环境配置控制，但这些配置只作为门禁开关和模式约束，不应被后续实现当作业务事实源：

| 配置面 | 语义 |
|---|---|
| `ENABLE_OUTPUT_SAFETY` | 是否启用输出安全门禁 |
| `OUTPUT_SAFETY_MODE` | `disabled`、`observe` 或 `enforce` 的运行模式 |
| `OUTPUT_SAFETY_POLICY_BACKEND` | 策略后端选择 |
| `OUTPUT_SAFETY_POLICY_ALWAYS_CALL` | 是否在无候选时仍保留策略调用 |
| `ENABLE_OUTPUT_SAFETY_GUARDRAILS` | 是否启用 Guardrails 候选采集 |

后续实现若引入新的模式或后端，应先更新本文档，再扩展代码。

## 4. 模式语义

### 4.1 `disabled`

`disabled` 表示输出安全门禁不参与当前回合的实质裁决。

要求如下：

1. 不应改变回复正文。
2. 不应引入新的输出改写路径。
3. 不应把禁用态误判为策略已通过。

### 4.2 `observe`

`observe` 表示输出安全只记录候选和审计信息，不改写用户可见文本。

要求如下：

1. 保留输出文本原样。
2. 保留候选和信号。
3. 允许用于分阶段加严和联调观测。

### 4.3 `enforce`

`enforce` 表示策略层开始对输出安全结果施加强制约束。

要求如下：

1. 只接受策略层给出的最终动作。
2. 不允许在业务层自行拼接修补文本。
3. 对于未就绪的改写能力，应显式失败，而不是静默回退。

## 5. 公开对齐面

后续实现只应依赖以下稳定对齐面：

| 对齐面 | 说明 |
|---|---|
| `vet_agent.output_safety` 包入口 | 输出安全的唯一跨包入口 |
| `OutputSafetyService` | 统一出口复核服务 |
| `OutputSafetyDetector` | 输出候选采集协议 |
| `OutputSafetyPolicyClient` | 输出策略裁决协议 |
| `OutputSafetyRepository` | 输出候选定义仓储协议 |
| `OutputSafetyReviewContext` | 响应复核上下文 |
| `OutputSafetyDecision` | 输出安全裁决结果 |
| `OutputSafetyCandidate` | 输出安全候选事实 |

外部实现应依赖这些协议和数据契约，而不是依赖软件包内部模块、私有函数或测试替身。

## 6. 有意保留的 TODO 项

以下项是当前版本**有意保留**的 TODO，不应被误读为遗漏：

1. `rewrite` 动作的正式实现仍待补齐。
2. 剂量相关风险候选目前保留为过渡边界，后续可迁移到统一策略层或进一步收束。
3. Guardrails 输出校验器仍是可选增强，不是强制生产依赖。
4. 输出安全的策略细化可能继续收敛到 OPA 层，不在业务层扩展分支逻辑。
5. 当后续引入更多输出安全 validator 时，应优先补充候选定义与策略契约，再考虑改变默认模式。

这些 TODO 的存在，是为了降低当前阶段的可用性风险和实现耦合，而不是为了长期保留临时规则。
