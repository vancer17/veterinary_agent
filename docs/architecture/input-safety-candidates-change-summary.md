# 基础输入安全候选变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：主业务对话入口、基础输入安全候选层、OPA 输入安全策略、Guardrails 提示注入检测器、输入安全响应与审计 metadata
>
> **不适用范围**：临床安全裁决、问诊状态机、RAG、长期记忆写入策略、输出安全策略、报告解析、管理接口完整改造

## 1. 变更目的

本次迁移将基础输入安全从旧版 `SafetyAgent.analyze` 与 `safety_rules` 关键词阻断路径中移出，收束为“结构化候选采集 + OPA 策略裁决”的前置门禁。

迁移前，输入安全、输出清洗、用户响应模板和规则表耦合在同一套旧规则路径内，容易出现以下问题：

1. 关键词命中在语义判断前直接阻断主链路。
2. 旧规则表同时承担候选定义、阻断动作和响应模板来源。
3. 输入安全和临床安全边界不清，导致后续模块难以判断应依赖哪个裁决结果。
4. 回退规则与正式策略并存，增加策略排障和代码评审心智负担。

迁移后，主链路采用以下边界：

| 能力 | 可信等级 | 位置 | 允许用途 |
|---|---|---|---|
| 结构化基础候选 | 可信输入事实候选 | 主链路开始阶段 | 表达输入为空、输入超长、附件字段异常、附件能力边界等非临床事实 |
| Guardrails 检测候选 | 可选检测器输出 | OPA 裁决前 | 识别提示注入等需要策略关注的输入风险候选 |
| 候选定义表 | 可信配置数据 | PostgreSQL 迁移初始化 | 维护候选编码、类别、默认严重级别和审计说明 |
| OPA 裁决 | 可信策略动作 | 输入安全门禁末端 | 将候选转换为 `allow`、`observe`、`escalate` 或 `block` |
| 输入安全响应 | 可信阻断结果 | 主链路进入临床前 | 在策略阻断或升级时生成非医学响应并停止后续领域处理 |

基础输入安全候选只表达“本轮输入存在需要策略关注的事实”。是否阻断、升级、观测或放行，统一由 OPA 裁决结果决定。

## 2. 职责边界

### 2.1 Agent 入口与主链路职责

主业务对话入口继续接收既有请求结构，并在完成身份、宠物资料、会话范围与 turn lock 后进入基础输入安全门禁。

主链路当前负责：

1. 在宠物上下文加载、临床安全判断、RAG、问诊状态和记忆读取之前执行输入安全裁决。
2. 将输入文本长度、附件数量、附件 MIME 类型、附件用途等结构化字段转为候选。
3. 在 OPA 返回阻断或升级动作时停止后续领域处理。
4. 将输入安全裁决摘要写入响应 metadata。
5. 在输入安全停止主链路时跳过记忆抽取，并记录明确的跳过原因。

主链路不负责：

1. 通过自然语言关键词扫描判断越权、非兽医范围或未开放能力。
2. 在 OPA 不可用时回退旧规则或本地关键词阻断路径。
3. 在基础输入安全层执行临床急诊分诊、疾病判断或治疗建议判断。
4. 根据输入安全候选直接写入长期记忆事实。
5. 从旧 `safety_rules.response_template` 回查用户响应文本。

### 2.2 候选定义仓储职责

候选定义仓储负责保存基础输入安全候选的配置化定义。它只提供候选定义，不执行文本扫描，也不决定最终动作。

候选定义当前负责：

1. 维护候选编码。
2. 维护候选类别。
3. 维护候选默认严重级别。
4. 维护候选说明和审计描述。
5. 支持后续策略、审计和运营对候选编码形成稳定引用。

候选定义不负责：

1. 保存关键词列表。
2. 生成响应模板。
3. 替代 Guardrails 或其他检测器。
4. 替代 OPA 做动作裁决。
5. 替代临床安全规则或临床语义模型。

### 2.3 Guardrails 检测器职责

Guardrails 在本阶段作为可选检测器接入，定位是“提示注入等输入风险候选来源”，不是最终阻断策略。

Guardrails 可以用于：

1. 采集提示注入候选。
2. 输出置信度、检测器来源和审计信息。
3. 在显式启用时参与 OPA 裁决输入。
4. 在集成测试中连接真实 LiteLLM 或外部模型网关验证检测链路。

Guardrails 不用于：

1. 替代 OPA 最终裁决。
2. 承载临床安全判断。
3. 作为旧关键词规则的包装层。
4. 在默认生产配置中直接强制拦截所有疑似输入。
5. 在检测器不可用时自动启用低质量本地规则兜底。

### 2.4 OPA 策略职责

OPA 是基础输入安全候选的最终动作裁决点。

OPA 当前负责：

1. 只消费应用侧提交的结构化候选。
2. 根据候选严重级别和策略规则输出动作。
3. 输出可审计的 message、reasons 和 signals。
4. 支持通过 Nginx 前缀暴露的 OPA Data API。
5. 支持外部开发环境中的真实策略服务联调。

OPA 不负责：

1. 扫描用户自然语言正文。
2. 维护提示注入关键词。
3. 承载临床医学推理。
4. 执行问诊状态机。
5. 读取业务数据库或长期记忆。

## 3. 接口兼容边界

### 3.1 已迁移的主业务入口

以下入口已纳入基础输入安全前置门禁：

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /agent/turns` | 已迁移 | 主业务对话入口，在进入临床链路前执行输入安全裁决 |
| `POST /openai/v1/responses` | 已迁移 | OpenAI Responses 风格兼容入口，与主业务入口使用同一裁决语义 |

上述入口的请求字段保持兼容，不要求调用方为本次输入安全迁移新增专用请求字段。

### 3.2 保持兼容的请求字段

以下字段为兼容保留，不属于本次输入安全迁移的变更面：

| 字段 | 兼容策略 |
|---|---|
| `input` | 文本与 OpenAI 风格消息输入继续兼容 |
| `attachments` | 附件引用结构保持不变；输入安全只读取结构化附件字段 |
| `metadata` | 继续作为非控制语义透传字段；只进入审计摘要，不作为关键词规则源 |
| `model` | 模型选择语义保持不变 |
| `stream` | 同步与 SSE 流式响应开关保持不变 |
| `turn_options.idempotency_key` | 幂等语义保持不变 |
| `scope_assertion` | 身份、宠物和会话范围语义保持不变 |
| `vet_context.pet_info` | 继续作为未验证资料兼容字段，不参与输入安全硬规则裁决 |

输入安全迁移不改变调用方构造请求的主要方式。后续如需要新增前端或 BFF 显式安全上下文字段，应通过单独接口契约变更处理。

### 3.3 新增或稳定的响应可观察字段

输入安全裁决通过响应 metadata 和安全信号对外可观察。

| 字段或行为 | 语义 |
|---|---|
| `metadata.input_safety_decision` | 本轮输入安全裁决摘要，包含动作、是否允许、原因、候选和信号 |
| `safety_signals` | 可包含输入安全候选经 OPA 裁决后形成的安全信号 |
| `status=blocked` | OPA 阻断本轮输入，主链路不进入临床处理 |
| `status=safety_escalated` | OPA 判断需要安全升级响应，主链路不进入临床处理 |
| `segments[].type=input_safety` | 表示本轮响应由基础输入安全链路生成 |
| `vet_result.route=input_safety_policy` | 表示响应路径来自输入安全策略裁决 |
| `metadata.memory_extraction.skipped_reason=input_safety_policy_stopped_main_chain` | 表示记忆抽取因输入安全停止主链路而跳过 |

后续模块应消费这些稳定字段，不应反向依赖软件包内部类名、调用栈或测试替身。

### 3.4 暂未纳入本次迁移的接口

以下接口或领域不以本文档作为输入安全裁决契约来源：

| 模块 | 当前状态 | 保留原因 |
|---|---|---|
| 报告解析与查询接口 | 暂未完整迁移 | 报告属于独立摄取和解析领域，需要单独定义附件能力边界 |
| 记忆管理接口 | 暂未完整迁移 | 记忆管理属于人工纠正或后台治理领域，需要独立安全策略 |
| 管理后台接口 | 暂未完整迁移 | 管理操作需要单独定义运维主体、权限范围和安全边界 |
| 输出清洗与安全复核 | 保留独立链路 | 输出侧约束与输入侧候选不是同一策略面 |
| 临床安全裁决 | 保留独立链路 | 临床急诊、禁忌、剂量和转诊判断需要语义与医学策略支撑 |

这些保留路径不是旧输入安全规则的回退机制。

## 4. 数据链落点

当前迁移后的逻辑落点如下：

| 阶段 | 作用 |
|---|---|
| 入口请求接收 | 接收文本、附件、metadata、模型、幂等键和可信范围声明 |
| 范围授权与 turn lock | 先完成身份、宠物、会话和单回合执行边界 |
| 输入安全上下文构造 | 汇总可信身份范围、输入文本长度、附件结构和审计 metadata |
| 基础候选采集 | 采集只依赖结构化字段的输入完整性和能力边界候选 |
| 可选检测器采集 | 在显式启用时采集 Guardrails 提示注入候选 |
| OPA 策略裁决 | 将候选转换为 allow、observe、escalate 或 block |
| 主链路分支 | allow、observe 继续执行；escalate、block 生成输入安全响应并停止后续领域处理 |
| 响应审计 | 写入输入安全裁决 metadata、安全信号和记忆抽取跳过原因 |

后续领域模块应把基础输入安全视为“主业务链路进入临床前的统一候选裁决边界”，而不是某个业务规则工具。

## 5. 候选类别语义

当前基础输入安全候选类别保持有限集合：

| 类别 | 当前含义 | 本阶段边界 |
|---|---|---|
| `integrity` | 输入完整性风险 | 只覆盖空输入、输入超长、附件数量超限、附件 MIME 类型缺失、附件用途不明等结构化字段问题 |
| `prompt_attack` | 越权或提示注入风险 | 由 Guardrails 等语义检测器支撑，不通过自定义关键词规则兜底 |
| `unopened_capability` | 非开放能力风险 | 当前只基于结构化附件用途拦截影像类附件能力边界，不基于自然语言关键词扫描 |
| `out_of_scope` | 明显非兽医业务范围候选 | 本阶段保留类别和策略入口，暂不实现自然语言硬规则判断 |

其中 `prompt_attack`、`unopened_capability` 和 `out_of_scope` 容易被误读为“关键词命中型规则”。本阶段的约束是：

1. `prompt_attack` 必须由检测器或后续语义模型支撑。
2. `unopened_capability` 如依赖自然语言内容判断，应进入后续语义检测器或能力路由，不应在基础输入安全层新增关键词扫描。
3. `out_of_scope` 当前只保留候选类型和策略占位，避免提前实现自定义规则状态机。
4. OPA 只裁决候选，不自行从原始文本中派生候选。

## 6. 策略动作语义

OPA 对基础输入安全候选输出有限动作：

| 动作 | 是否进入主链路 | 语义 |
|---|---|---|
| `allow` | 是 | 无候选或策略允许本轮继续执行 |
| `observe` | 是 | 记录候选和信号，但不阻断临床链路 |
| `escalate` | 否 | 生成安全升级响应，不进入宠物上下文、临床安全、RAG 或记忆读取 |
| `block` | 否 | 生成阻断响应，不进入宠物上下文、临床安全、RAG 或记忆读取 |

`observe` 不是隐式风险放任。它表示当前策略选择记录风险并继续主链路，后续可以通过 OPA 策略调整为升级或阻断，而不改变业务代码。

`escalate` 在当前基础输入安全链路中同样会停止主链路。后续如需要“升级但继续执行”的语义，应先调整外部契约和响应行为，不能仅修改内部状态枚举。

## 7. 配置与环境边界

当前基础输入安全相关配置如下：

| 配置 | 当前默认 | 作用 |
|---|---|---|
| `ENABLE_INPUT_SAFETY` | `true` | 是否启用基础输入安全服务 |
| `INPUT_SAFETY_POLICY_BACKEND` | `opa` | 输入安全策略后端；正式路径使用 OPA |
| `INPUT_SAFETY_POLICY_ALWAYS_CALL` | `true` | 无候选时是否仍调用 OPA 形成审计裁决 |
| `INPUT_SAFETY_OPA_BASE_URL` | `http://opa:8181/v1` | OPA REST API 基准地址，可包含 Nginx 前缀 |
| `INPUT_SAFETY_OPA_PACKAGE_PATH` | `vet_agent.input_safety` | OPA Data API package 路径 |
| `INPUT_SAFETY_OPA_RULE_NAME` | `decision` | OPA 裁决规则名称 |
| `INPUT_SAFETY_OPA_AUTH_TOKEN` | 空 | OPA 鉴权令牌；开发环境可为空，生产环境按网关策略配置 |
| `ENABLE_INPUT_SAFETY_GUARDRAILS` | `false` | 是否启用 Guardrails 提示注入检测器 |
| `INPUT_SAFETY_GUARDRAILS_MODEL` | `openai/qwen-plus` | Guardrails 检测器使用的模型 |
| `INPUT_SAFETY_PROMPT_INJECTION_THRESHOLD` | `0.8` | Guardrails 提示注入候选阈值 |

生产环境默认要求基础输入安全与 OPA 可用。Guardrails 默认关闭，是为了避免在缺少 shadow 观测和误判复核前把模型检测结果直接纳入强制链路。

## 8. 测试与外部服务边界

当前测试策略分为本地单元测试和显式外部集成测试。

| 测试类型 | 默认行为 | 边界 |
|---|---|---|
| 本地单元测试 | 不依赖真实 OPA、Guardrails 或外部数据库 | 使用显式注入的测试替身，但必须遵守相同可观察契约 |
| OPA 集成测试 | 需要显式提供外部 OPA 地址或启用本地 OPA smoke | 验证真实 OPA Data API 对 block、observe、escalate 的裁决行为 |
| Guardrails 集成测试 | 默认跳过，需要显式开启 | 验证真实 Guardrails 与模型网关检测链路，不作为默认 CI 必跑项 |
| API 测试 | 默认不启动外部服务 | 覆盖输入安全响应契约、metadata 和记忆抽取跳过行为 |

外部开发环境当前可提供 OPA、LiteLLM、PostgreSQL、Mem0 等依赖服务。涉及外部服务的测试应通过显式环境变量启用，避免把临时开发服务变成默认 CI 的隐性依赖。

## 9. 有意保留的 TODO

以下 TODO 是本次迁移有意保留的工程边界，用于避免基础输入安全退化为自定义规则状态机。

| TODO | 边界说明 | 后续建议 |
|---|---|---|
| `out_of_scope` 语义检测 | 当前只保留候选类别，不实现自然语言关键词命中 | 后续接入 LiteLLM 结构化输出、Guardrails 或专用分类器生成候选，再交给 OPA 裁决 |
| 非开放能力自然语言判断 | 当前只基于结构化附件用途处理影像附件能力边界 | 后续通过能力路由或语义检测器识别“要求影像判读”等意图，不在基础服务内新增词表 |
| Guardrails 生产强制启用 | 当前默认关闭，避免未观测误判率前进入强制门禁 | 先在开发或 shadow 模式记录命中、误判和漏判，再按发布流程切换 |
| OPA 策略精细化 | 当前策略以候选严重级别映射动作为主 | 后续可按来源、置信度、环境、调用方、候选组合和审计等级扩展 Rego |
| OPA 鉴权与控制面 | 开发环境可无鉴权；生产环境应由 Nginx 或内网策略限制访问 | 后续补充 token、mTLS、bundle 发布、策略版本审计和决策日志接入 |
| 候选定义治理界面 | 当前通过 Alembic 初始化基础定义 | 后续如需要运营维护，应建立管理接口、审批流程和变更审计 |
| 报告领域附件能力边界 | 报告解析未纳入本次基础输入安全统一迁移 | 后续在报告域定义独立摄取策略，再评估是否与输入安全候选共享编码 |
| 输出安全迁移 | 输出清洗仍是独立链路，不读取旧输入安全响应模板 | 后续输出侧可引入 Guardrails 与 OPA，但不得复用输入候选动作语义 |
| 全量真实 API 集成测试 | 当前默认 API 测试不启动真实数据库、OPA 和 Guardrails | 后续可在专用环境中增加端到端烟测，并与默认 CI 分层 |
| 候选置信度治理 | 当前结构化候选多为确定性事实，Guardrails 候选依赖检测器置信度 | 后续需要定义不同检测器的阈值、校准方式和回归评估集 |

## 10. 明确不做事项

为了保持本次迁移边界清晰，以下事项不属于当前阶段：

1. 不在基础输入安全层实现临床急诊分诊。
2. 不在 OPA 策略中扫描用户自然语言文本。
3. 不保留旧 `safety_rules` 作为输入安全回退路径。
4. 不使用旧 `response_template` 生成输入安全响应。
5. 不把 Guardrails 结果直接等同于最终阻断动作。
6. 不用自定义关键词列表判断提示注入、越权、非兽医范围或自然语言能力边界。
7. 不让输入安全候选直接产生长期记忆事实。
8. 不把本地测试替身作为生产回退策略。
9. 不在 OPA 不可用时继续进入临床主链路。
10. 不把报告、记忆管理和管理后台接口一并纳入本次迁移。

## 11. Fail Fast 规则

主业务入口遇到以下情况应拒绝请求或停止主链路，而不是进入兼容兜底：

| 场景 | 预期行为 |
|---|---|
| 基础输入安全服务未就绪 | 拒绝进入主业务链路 |
| OPA 策略客户端配置不完整 | 拒绝进入主业务链路 |
| OPA 调用失败或返回结构不合法 | 拒绝进入主业务链路，不回退本地规则 |
| `INPUT_SAFETY_POLICY_BACKEND` 配置为未知值 | 启动或容器构建阶段失败 |
| 正式容器未配置输入安全所需数据库连接 | 启动就绪检查失败 |
| Guardrails 显式启用但模型网关配置不可用 | 检测器不可就绪，不能静默降级为关键词规则 |
| OPA 返回 `block` | 返回输入安全阻断响应，跳过后续领域处理和记忆抽取 |
| OPA 返回 `escalate` | 返回输入安全升级响应，跳过后续领域处理和记忆抽取 |
| 业务模块尝试重新读取旧安全规则 | 在代码评审中拒绝 |
| 业务模块尝试增加输入安全关键词回退路径 | 在代码评审中拒绝 |

测试环境可以显式注入替身，但替身必须服务于测试隔离，不得被包装为生产故障兜底。

## 12. 后续实现对齐原则

后续迁移临床安全、问诊状态、RAG、记忆、报告、输出安全和策略治理时，应遵循以下约束：

1. 基础输入安全只处理进入临床链路前的输入级候选。
2. 临床急诊、禁忌、剂量、转诊和治疗建议边界应留在临床安全域。
3. 提示注入、越权和非业务范围判断如涉及自然语言语义，必须由检测器或结构化模型结果支撑。
4. OPA 只裁决结构化候选和上下文摘要，不自行解析原始用户文本。
5. 新增候选类型时，应先定义候选编码、来源、严重级别、审计说明和策略动作，再接入主链路。
6. 新增检测器时，应输出候选，不应直接返回业务响应。
7. 新增策略时，应优先扩展 Rego 裁决规则，不应在业务代码中加入并行动作判断。
8. 业务响应应使用 OPA 裁决 message 和安全信号，不应回查旧模板。
9. 默认 CI 应覆盖无外部依赖的契约测试；真实 OPA、Guardrails 和模型网关测试应作为显式集成层。
10. 所有回退路径必须能被清楚区分为测试替身、开发显式配置或正式生产路径。

## 13. 验收基线

当前阶段后续修改不应破坏以下基线：

1. 主业务入口在进入宠物上下文和临床安全前执行基础输入安全裁决。
2. 输入安全不读取旧 `safety_rules` 表作为输入阻断来源。
3. 输入安全不使用旧 `response_template` 生成响应。
4. OPA 策略不扫描用户自然语言文本。
5. 结构化空输入、输入超长、附件数量超限、附件 MIME 类型缺失可以生成阻断候选。
6. 附件用途不明可以生成观测候选。
7. 结构化影像类附件用途可以生成未开放能力候选。
8. Guardrails 提示注入检测器默认关闭，显式启用时只生成候选。
9. OPA 可以输出 `allow`、`observe`、`escalate` 和 `block` 四类动作。
10. `block` 和 `escalate` 均停止主链路，并记录记忆抽取跳过原因。
11. 正常放行路径的响应 metadata 包含输入安全裁决摘要。
12. 本地单元测试不依赖真实外部服务。
13. 真实 OPA 与 Guardrails 测试必须通过显式环境变量启用。
14. 后续模块不需要了解输入安全软件包内部实现即可消费稳定响应契约。
