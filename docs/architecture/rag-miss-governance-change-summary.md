# RAG 无命中治理变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：回答相关 RAG 无命中、治理记录持久化、知识缺口审计、Admin API 查询与人工状态更新
>
> **不适用范围**：回答生成、临床安全裁决、知识自动审核、知识 chunk 生产、向量生成和发布审批

## 1. 变更目的

本次迁移的目标，是让回答相关 RAG 在无已审核、已启用且可召回的知识资产时形成可治理记录，同时保持运行时 Fail Fast。

迁移后，无命中不再被静默处理为默认回答、空证据回答、关键词路径或本地知识兜底，而是在编排器调用回答 RAG 的边界处记录知识缺口，再继续抛出原始异常。

## 2. 运行时边界

回答相关 RAG 的运行时控制流如下：

1. 上游问诊状态与回答充分性裁决确认当前任务可以回答。
2. 编排器构造 `AnswerRagRequest` 并调用 `AnswerRagService.retrieve()`。
3. 回答 RAG 发现依赖失败、契约错误或无有效命中时抛出 `AnswerRagError`。
4. 编排器捕获异常并调用 `RagMissGovernanceService.record_miss(...)` 留痕。
5. 治理记录写入后，编排器继续抛出原始异常。
6. API 层返回服务不可用语义，不进入回答生成。

该链路的关键约束是：治理留痕只服务后续资产补充，不改变当前回合的业务结果。

## 3. 数据库边界

新增表 `rag_retrieval_misses` 用于保存知识缺口治理记录。表中包含以下核心信息：

| 字段类别 | 用途 |
|---|---|
| 请求范围 | 保存 `request_id`、`trace_id`、`user_id`、`pet_id`、`session_id`，便于回溯触发范围 |
| 任务上下文 | 保存任务标识、任务键、任务域和任务标题，便于按业务域聚合缺口 |
| 检索输入 | 保存结构化 query、问诊状态、回答充分性和语义抽取快照 |
| 召回参数 | 保存 chunk 类型、`top_k`、`min_score` 和领域过滤条件 |
| 失败信息 | 保存失败原因、异常类型、异常消息和结构化异常详情 |
| 治理字段 | 保存治理状态、备注、关联导入批次和关联正式 chunk |
| 聚合字段 | 保存用户文本摘要与 `dedupe_key`，便于聚合同类知识缺口 |

业务层不直接访问该表模型。数据库访问只通过 `RagMissRepositoryProtocol` 暴露，并由 `PostgresRagMissRepository` 实现。

## 4. 服务边界

新增 `vet_agent.rag_miss_governance` 包，作为 RAG 无命中治理的唯一业务边界。

| 模块 | 职责 |
|---|---|
| `models.py` | 定义治理请求、草稿、记录视图和状态枚举 |
| `ports.py` | 定义记录器、仓储和治理服务协议 |
| `service.py` | 标准化治理请求，生成摘要、聚合键和持久化草稿 |
| `postgres_repository.py` | 通过 SQLAlchemy 访问 `rag_retrieval_misses` 表 |
| `errors.py` | 定义治理链路专用异常 |

跨包调用只能通过 `vet_agent.rag_miss_governance.__init__` 暴露的顶层对象完成，避免业务层直接绑定内部实现路径。

## 5. 管理端入口

新增 Admin API：

| 接口 | 用途 |
|---|---|
| `GET /admin/rag/misses` | 分页查询 RAG 无命中治理记录，可按范围、状态和任务域过滤 |
| `PATCH /admin/rag/misses/{miss_id}` | 更新治理状态、备注、关联导入批次和关联正式 chunk |

这些接口只改变治理记录，不触发知识发布、不生成 embedding、不修改回答 RAG 结果，也不重新驱动当前会话。

## 6. 不允许的回退路径

本迁移明确不恢复以下旧路径：

1. 默认回答模板。
2. 关键词或正则规则回答。
3. 本地文件知识兜底。
4. 开发样例 JSON 兜底。
5. seed 资产静态检查或静态命中兜底。
6. 无命中时返回空 `AnswerRagResult`。

如果回答 RAG 无法提供合格证据，当前回合必须失败，并把失败上下文记录到治理表。

## 7. 后续对齐原则

后续知识补充流程应从 `rag_retrieval_misses` 聚合同类缺口开始，经人工确认、材料准备、知识导入、chunk 生成、embedding 生成和审核发布后，才允许进入正式回答 RAG 召回。

该治理链路可以扩展后台聚合视图、批量标记、与知识导入批次的自动关联，但不应把这些能力放回运行时回答链路中。
