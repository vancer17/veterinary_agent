# 长期记忆候选抽取变更总结

> **文档状态**：迁移完成后的对齐基线
>
> **适用范围**：主业务回合结束后的长期记忆候选抽取入队、后台 Worker 异步抽取、显式来源边界、多任务来源透传、响应元数据和后续治理对接
>
> **不适用范围**：权威长期事实写入、删除与纠正治理、Mem0 语义投影、临床安全裁决、问诊状态机、RAG 检索、自然语言回复生成

## 1. 变更目的

本次迁移的目标，是把长期记忆候选抽取从旧版规则回退、关键词路径、手写 JSON 修复和“抽到就写”的松散模式中收束出来，改为“主回合显式来源入队 + 后台 Worker 结构化抽取”的异步链路。

迁移后，长期记忆候选抽取只回答一个问题：

> 当前回合中，哪些显式来源片段里存在可供后续治理层评估的长期记忆候选？

它不回答以下问题：

1. 这些候选是否最终应该写入权威事实库。
2. 这些候选是否需要删除、纠正或覆盖旧事实。
3. 这些候选是否应该同步到 Mem0。
4. 这些候选是否构成临床风险或问诊动作。

迁移后，主业务回合不再同步等待候选抽取完成。主回合只负责构造显式来源、写入 `memory_candidate_extraction` 后台任务，并在响应 metadata 中返回任务摘要。候选抽取结果由后台 Worker 写入任务结果审计。

## 2. 作用边界

### 2.1 允许承担的职责

长期记忆候选抽取允许做的事情只有以下几类：

1. 接收已经完成输出安全复核的回合响应。
2. 接收显式来源片段，优先保留多任务边界。
3. 通过结构化模型抽取候选提议。
4. 将抽取结果整理为稳定的抽取结果对象和后台任务结果审计。
5. 在依赖缺失、契约不符或结构化输出失败时明确失败，并交由后台任务状态表达 retry 或 dead letter。

### 2.2 明确不承担的职责

长期记忆候选抽取不负责以下事项：

1. 决定是否写入权威长期事实库。
2. 决定是否删除、纠正或覆盖旧事实。
3. 决定是否进入 Mem0 语义投影。
4. 维护关键词、正则、默认分类或手写回退规则。
5. 将请求侧自报宠物资料当作权威长期事实。
6. 将多任务文本自动拼接后再做事实混淆抽取。
7. 代替临床安全裁决、问诊状态机或回答充分性判断。
8. 在主业务回合中同步调用模型完成候选抽取。
9. 把后台任务结果中的候选直接解释为权威长期事实。

### 2.3 来源边界约束

长期记忆候选抽取的主路径应以显式来源片段为准。

| 约束 | 含义 |
|---|---|
| 显式来源优先 | 上游应提供 `memory_extraction_sources`，由编排层显式划分来源边界 |
| 多任务隔离 | 不应把多个任务的文本混成一个无边界来源再做抽取 |
| 单回合兼容 | 旧调用面若未提供显式来源，可保留单回合来源构造，以避免立刻破坏兼容 |
| 不做隐式回退 | 不允许再通过关键词、正则或默认枚举补齐候选 |

需要强调的是：单回合来源构造仅是兼容措施，不是推荐数据入口，也不是关键词或规则回退。

### 2.4 运行边界

长期记忆候选抽取现在依赖可持久化后台任务底座运行。

| 阶段 | 职责 |
|---|---|
| 主业务回合 | 构造 `memory_extraction_sources`，写入 `memory_candidate_extraction` 后台任务，返回任务摘要 |
| 后台 Worker | 领取任务，重建候选抽取上下文，调用结构化抽取器，写入任务结果审计 |
| 后续治理层 | 读取候选结果并决定是否写入权威事实库，当前阶段尚未实现 |

`app` 与 `worker` 复用同一个应用镜像，通过不同启动命令区分运行角色。生产环境不得为候选抽取维护第二套镜像或在现场构建 worker 镜像。

## 3. 兼容接口

### 3.1 稳定导出面

当前长期记忆候选抽取对外保留以下稳定入口：

| 入口 | 语义 |
|---|---|
| `vet_agent.memory_extraction.MemoryExtractionAgent` | 长期记忆候选抽取服务主入口 |
| `vet_agent.memory_extraction.MemoryExtractionRequest` | 结构化抽取请求 |
| `vet_agent.memory_extraction.MemoryExtractionResult` | 结构化抽取结果或显式失败状态 |
| `vet_agent.memory_extraction.MemoryCandidateProposal` | 长期记忆候选提议 |
| `vet_agent.agents.MemoryExtractionAgent` | 兼容导出入口 |
| `vet_agent.agents.MemoryFactCandidate` | 向后兼容别名 |

上述入口用于保证上游编排、后台 Worker、测试替身和后续实现可以平滑切换，不表示内部实现细节是稳定契约。

### 3.2 响应 metadata

当前主回合会在响应 metadata 中保留以下稳定摘要：

| 字段 | 语义 |
|---|---|
| `memory_extraction_sources` | 本轮长期记忆候选抽取可见的显式来源片段 |
| `memory_extraction` | 后台任务入队摘要、显式跳过原因或禁用状态 |
| `strategy` | `background_task_queued`、`background_task_disabled` 或 skipped 状态 |
| `fallback_reason` | 显式禁用、跳过或入队不可用原因 |
| `task_id` | 已入队后台任务标识；未入队时为空 |
| `task_status` | 后台任务初始状态或跳过状态 |
| `task` | 后台任务轻量摘要 |
| `proposal_count` | 主回合返回时固定为 0，不表示本轮没有候选 |
| `proposal_keys` | 主回合返回时为空，真实候选键记录在后台任务结果中 |
| `stored_fact_count` | 当前阶段固定为 0，长期事实写入治理尚未接入 |
| `stored_fact_keys` | 当前阶段为空，长期事实写入治理尚未接入 |

这些字段只用于审计、调试和后续治理对齐，不应被当作长期事实本体，也不应被前端或调用方解释为候选抽取已经完成。

### 3.3 后台任务结果

`memory_candidate_extraction` 后台任务执行完成后，会在任务结果中记录候选抽取摘要。

| 字段 | 语义 |
|---|---|
| `proposal_count` | 后台结构化抽取得到的候选数量 |
| `proposal_keys` | 候选事实键摘要 |
| `proposals` | 候选提议结构化摘要 |
| `stored_fact_count` | 当前阶段固定为 0 |
| `stored_fact_keys` | 当前阶段固定为空 |
| `fact_write_status` | 当前阶段为 `TODO` |
| `fact_write_reason` | 标记长期事实写入治理尚未实现 |

后台任务结果是“候选抽取审计”，不是权威事实库。后续治理层可以消费该结果，但必须独立完成写入裁决、冲突处理、确认流程和审计落库。

### 3.4 配置边界

当前长期记忆候选抽取只保留显式开关 `ENABLE_MEMORY_EXTRACTION`。

后台任务运行参数由可持久化后台任务底座统一承载，例如：

| 配置 | 语义 |
|---|---|
| `BACKGROUND_TASKS_MAX_ATTEMPTS` | 后台任务最大尝试次数 |
| `BACKGROUND_TASKS_WORKER_BATCH_SIZE` | Worker 单轮领取数量 |
| `BACKGROUND_TASKS_WORKER_LEASE_SECONDS` | 任务租约时长 |
| `BACKGROUND_TASKS_WORKER_POLL_INTERVAL_SECONDS` | Worker 空轮询间隔 |

这些参数只控制任务执行节奏，不改变候选抽取语义，也不承担写入治理策略。

以下旧配置已不再作为本阶段稳定接口：

1. `ENABLE_LLM_MEMORY_EXTRACTION`
2. `MEMORY_EXTRACTION_MIN_CONFIDENCE`

这意味着后续实现不应再依赖“启用 LLM 路径”和“最低置信度阈值”这类额外抽象分岔来控制抽取主逻辑。

## 4. 有意保留的 TODO

以下项是本阶段有意保留的待办，不代表实现缺失：

| TODO | 说明 |
|---|---|
| 写入治理层独立化 | 长期记忆候选抽取与权威事实写入的 OPA 裁决应继续收束到独立治理层 |
| 删除与纠正治理 | 冲突、修正、删除和覆盖不应在抽取层判断 |
| Mem0 投影分流 | 长期记忆候选抽取不直接负责语义投影落地 |
| 后台任务管理界面 | 当前只提供任务持久化状态和结果审计，不新增管理 API |
| 候选结果物化表 | 当前候选只记录在后台任务结果中；是否新增独立候选表由后续写入治理阶段决定 |
| 事实目录收敛 | `fact_type`、`fact_key` 的正式目录后续应进一步收口 |
| `TODO` 事实类型 | 当事实大类尚未正式纳入目录时，允许显式保留 `TODO`，避免隐式默认分类 |
| 时间范围收敛 | `UNCLEAR` 与 `UNKNOWN` 仍作为受控枚举值保留，后续可由治理层再统一收敛语义 |
| 旧别名兼容期 | `MemoryFactCandidate` 目前保留为兼容别名，后续可在调用面完成切换后再清理 |
| 显式来源编排强化 | 上游仍需逐步把所有多任务回合都改为显式来源片段输入 |

这些 TODO 不应通过新增关键词规则、默认分类、隐式回退或手写解析提前补齐。

## 5. 后续对齐原则

后续凡是涉及长期记忆候选抽取的变更，默认遵守以下原则：

1. 先保持来源边界清晰，再谈抽取结果丰富度。
2. 先保持结构化输出稳定，再谈治理层细化。
3. 任何依赖缺失、契约不符或结构化输出失败都应显式失败。
4. 不允许重新引入关键词、正则、默认分类或 JSON 修复路径。
5. 不允许把抽取层和写入治理层混成同一个职责面。
6. 多任务场景必须保留任务级来源边界，不能因为同属一个 session 就自动合并。
7. 主业务回合不得重新同步等待候选抽取完成；需要候选结果时应通过后台任务状态或后续治理产物读取。
8. 后台任务结果不得成为权威事实、冲突状态或 Mem0 投影状态的唯一可信源。

## 6. 与后续模块的关系

长期记忆候选抽取与以下模块存在协作关系，但不共享职责：

| 模块 | 关系 |
|---|---|
| `可持久化后台任务` | 承载长期记忆候选抽取的异步执行、重试和死信审计 |
| `记忆读取` | 提供权威事实和历史上下文，不参与候选抽取决策 |
| `长期事实写入` | 负责候选是否入库，不在本阶段实现 |
| `删除与纠正治理` | 负责冲突处理和事实修正，不在本阶段实现 |
| `Mem0 语义投影` | 负责语义记忆召回，不直接接管候选抽取结果 |
| `多任务拆分` | 负责产生任务边界，是候选来源的重要上游 |
| `输出安全复核` | 负责回合末安全边界，不决定长期事实写入 |

## 7. 结论

长期记忆候选抽取现在的定位是“异步结构化候选提取层”，而不是“长期事实写入层”或“记忆治理层”。

只要后续实现继续遵守显式来源、显式失败和职责分层这三个原则，这一层就可以稳定作为后续长期记忆治理链路的输入端。
