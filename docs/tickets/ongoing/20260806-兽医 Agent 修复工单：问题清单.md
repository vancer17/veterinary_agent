# 兽医 Agent 修复工单：问题清单

## 0. 工单说明

本文用于归档兽医 Agent 在能力评估、业务联调和代码审查中暴露的问题。本文仅描述需要修复的问题、影响范围、证据与风险，不包含具体修复方案。

## 1. P0：问诊漏斗不收敛，导致最终答复难以产出

### 问题描述

系统在多轮问诊中存在明显的状态收敛问题。即使用户已经持续补充关键信息，系统仍可能停留在追问阶段，无法进入阶段性最终回答。

### 主要现象

- 用户已回答精神、食欲等信息后，系统仍重复追问相同信息。
- 用户已经提供较完整上下文后，系统仍继续要求补充低价值或不相关槽位。
- 用户明确表达“不要再追问、直接回答”时，系统仍继续追问。
- 诊断类问题容易被长期卡在问诊漏斗中，最终答复无法稳定产出。

### 典型证据

- 用户说“精神食欲都正常”，系统仍提示缺少“精神状态、食欲饮水”。
- 耳部、皮肤、益生菌等场景中，系统仍要求补充“呕吐情况”等低相关信息。
- 年龄、体重、时间等槽位曾出现误抽取，例如把“两个喷嚏”“一个多月”“5kg/8kg”等内容错误纳入问诊状态。
- 在多轮逼答测试中，大量病例无法进入最终回答阶段。

### 影响范围

- 多轮问诊体验。
- 最终答复产出率。
- 用户对 Agent 专业性和可用性的判断。
- 后端业务侧对话闭环能力。
- C 端灰度上线稳定性。

### 风险等级

P0。该问题会直接阻断 Agent 的核心问诊闭环。

## 2. P0：安全层依赖窄关键词，隐匿高风险场景存在漏判

### 问题描述

安全层对显性急症词和毒物词有一定识别能力，但对缺少明确关键词、依赖多症状组合和上下文语义判断的高风险场景识别不足。

### 主要现象

- 显性急症词命中时可以升级。
- 未出现显性急症词时，部分高风险场景可能进入普通追问路径。
- 否定表达可能误触发急症判断。
- 知识咨询和真实摄入事件存在混淆风险。

### 典型证据

- “尿闭全堵、GDV、发绀、难产、木糖醇、晕厥”等显性急症场景可以正确升级。
- “老年猫多饮多尿并消瘦”“公猫尿少尿频但尚未完全尿不出”等隐匿高风险场景曾出现漏判。
- “不是完全尿不出”这类否定表达存在被误识别为尿闭急症的风险。
- “狗能吃巧克力吗”这类纯知识咨询可能被误当作正在发生的中毒事件。

### 影响范围

- 急症分诊安全。
- 毒物/人药风险识别。
- 线上医疗安全边界。
- 用户就医时机判断。
- C 端上线风险。

### 风险等级

P0。该问题存在延误急症处理的风险。

## 3. P1：缺少越界与主体识别，非目标请求会进入犬猫问诊流程

### 问题描述

系统缺少稳定的入口主体识别和意图识别能力。人类医疗、非犬猫动物、非医疗任务、无效输入等请求可能被错误导入犬猫问诊漏斗。

### 主要现象

- 人类医疗问题可能被当作宠物医疗问题处理。
- 非犬猫物种可能进入默认犬猫问诊流程。
- 写诗、写代码、乱码等非医疗请求可能被问诊状态机接管。
- 请求主体不清时，系统容易直接套用宠物问诊模板。

### 典型证据

- “我头疼吃什么”这类人类医疗问题可能被错误引导到兽医语境。
- 兔、仓鼠等非犬猫物种问题可能被塞入猫狗问诊槽位。
- 非医疗内容仍可能触发“起病时间、精神食欲”等问诊追问。

### 影响范围

- 入口路由准确性。
- 用户体验。
- 医疗责任边界。
- 非目标业务请求处理。
- Agent 专业可信度。

### 风险等级

P1。该问题不一定直接导致急症漏判，但会扩大系统职责边界并造成错误对话路径。

## 4. P1：外部 model 字段透传 LiteLLM，导致模型调用失败

### 问题描述

系统曾将调用方请求体中的 `model` 字段直接透传给 LiteLLM。若调用方传入的模型名未在 LiteLLM 注册，底层模型调用会失败，并触发兜底响应。

### 主要现象

- 调用方传入非 LiteLLM 注册模型名时，ResponseComposer 无法正常生成回答。
- 系统返回“当前模型服务暂时不可用”等兜底话术。
- 后端 BFF 需要额外规避该问题，避免传入不兼容模型名。

### 典型证据

- LiteLLM 日志出现：`ProxyModelNotFoundError: Invalid model name passed in model=vet-agent-default`。
- 使用 `qwen-plus` 或省略外部 `model` 字段后，调用恢复正常。
- `vet-agent-default`、未注册的 `qwen-max` 等值会触发失败路径。

### 影响范围

- 模型网关稳定性。
- 业务方接入兼容性。
- 多模型路由治理。
- Agent 最终回答生成能力。

### 风险等级

P1。该问题会造成可用性下降，但通常不直接产生医疗安全风险。

## 5. P1：常见病症知识未结构化治理，追问容易退化为固定模板

### 问题描述

常见病症知识如果只存在于文档或代码硬编码中，系统难以稳定利用其中的病症特异追问、分诊依据、红旗提示和居家护理信息。缺少结构化知识资产治理时，追问容易退化为固定槽位模板。

### 主要现象

- 不同主诉可能收到高度相似的追问。
- 系统容易反复询问“食欲、精神、是否萎靡”等通用问题。
- 病症特异信息没有稳定进入 RAG 召回和追问规划。
- 知识来源、审核状态、发布版本和回滚记录不易审计。

### 典型证据

- 业务模拟请求中，不同场景曾出现相似追问。
- `common_conditions_handbook.md` 包含大量病症特异追问，但原始 Markdown 不适合作为稳定运行时知识源。
- 工单包中另有 `vet_conditions.json`，说明临床知识已具备结构化落库基础。
- 若缺少发布和审核流程，临床知识更新难以满足生产运维要求。

### 影响范围

- RAG 召回质量。
- 动态追问质量。
- reasoning_display 诊断证据展示。
- 后台运维和临床审核。
- 知识版本可追溯性。

### 风险等级

P1。该问题主要影响回答质量、运维审计和知识治理能力。

## 6. 保留能力记录

以下能力在评估中表现较好，作为后续回归审查的保留项记录：

- LLM 生成追问的自然表达能力较好。
- 最终答复在成功进入回答阶段后，能覆盖分诊分级、可能方向和就医兜底。
- 抗提示泄露、抗诱导和抗蒸馏能力表现较稳定。
