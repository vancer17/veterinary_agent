# 兽医 Agent 修复工单：问诊语义抽取空结果与过度追问

## 0. 工单说明

本文用于记录预发布语义复测中暴露的问诊语义抽取、状态收敛和回答准入问题。本文只描述背景、现象、证据、影响范围、修复边界和验收口径，不包含具体实现方案。

## 1. 背景

临床安全阶段 0 至阶段 5 已完成工程迁移，预发布环境已具备以下基线：

1. 临床安全语义抽取、pgvector 召回、`required_context` 前提评估与 OPA 裁决主链路可用。
2. 模糊分诊不会在证据不足时直接升级急诊。
3. 用户明确否认的症状不应被当作正向急症事实。
4. 问诊链路应通过结构化语义、问诊状态、回答充分性策略和追问 RAG 完成多轮收敛。

为检查真实生产语义表现，预发布环境执行了口语化急诊、单轮问诊、多轮问诊和 answer-now 控制组请求。其中，低风险“换粮后软便，精神食欲正常，明确否认呕吐和血便”场景出现连续追问，后续四组复测确认该问题可稳定复现。

主要记录文件：

```text
logs/console.log
```

主要响应目录：

```text
/tmp/soft-stool-retest-20260821172210-623446/
```

## 2. 问题内容

### 2.1 问诊语义抽取返回空结果

#### 问题描述

用户原文中明确包含起病时间、换粮、大便形态、精神状态、食欲饮水、呕吐否认和血便否认，但问诊语义抽取结果持续返回：

```text
facts = []
observations = []
```

同时结果被标记为：

```text
strategy = litellm_response_format
trusted = true
confidence = 0.95 / 0.98
```

这意味着当前系统只确认了结构化调用成功和整体置信度，没有识别“原文存在明确事实但输出为空”的覆盖率问题。

#### 复测证据

| 复测 | 输入特点 | HTTP / 耗时 | 问诊语义结果 | 最终状态 |
|---|---|---:|---|---|
| A 原始输入复测 | 原口语化场景 | `200 / 39.75s` | `facts=[]`, `observations=[]` | `requires_followup` |
| B 规范化表达 | 更明确的时间、软便、无血、精神正常、食欲饮水正常、无呕吐/干呕 | `200 / 39.84s` | `facts=[]`, `observations=[]` | `requires_followup` |
| C answer-now 控制组 | 明确要求先给阶段建议、不要继续追问 | `200 / 37.62s` | `facts=[]`, `observations=[]`, `answer_now=false` | `requires_followup` |
| D 第二轮补充 | 逐项回答精神、玩耍、呼唤反应、进食饮水、呕吐/干呕/反流/流涎/舔唇、大便、换粮时间 | `200 / 55.21s` | `facts=[]`, `observations=[]` | `requires_followup` |

#### 影响

1. 用户已明确回答的槽位无法进入 `consultation_state.slots`。
2. 回答充分性策略持续收到缺失槽位。
3. 追问 RAG 继续生成已回答问题的细化追问。
4. 多轮问诊无法稳定收敛。

### 2.2 正常状态与否定状态未被消费为问诊证据

#### 问题描述

以下表达均属于用户明确提供的高价值问诊事实：

```text
精神挺好 / 精神正常
饭和水都正常 / 食欲正常、饮水正常
没有呕吐
没有干呕
没有血便
前天开始
换新猫粮
大便有一点软
```

但问诊状态中仅保留宠物画像预填信息：

```text
species
life_stage_or_age
weight
```

消化道问诊域要求的以下槽位仍被判定为缺失：

```text
onset
mental_status
appetite
vomiting
stool
```

#### 影响

1. “用户明确报告正常”被误当作未知。
2. “用户明确否认症状”被误当作未知。
3. 否定证据无法缩短追问漏斗。
4. 系统表现为忽略或不信任用户已提供的信息。

### 2.3 answer-now 控制意图未被识别

#### 问题描述

测试 C 的用户输入明确包含：

```text
请先根据现有信息给阶段建议，不要继续追问
```

但问诊语义输出为：

```text
intent.answer_now = false
intent.wants_triage = false
intent.raw_intent = ""
```

导致回答充分性策略无法进入用户显式要求阶段回答的路径。

#### 影响

1. 用户显式控制意图失效。
2. answer-now 场景仍进入追问。
3. 多轮问诊体验进一步恶化。
4. 后续无法可靠验证“用户要求先答”与安全追问之间的策略优先级。

### 2.4 临床安全语义与问诊语义存在跨 Agent 不一致

#### 问题描述

同一请求中，临床安全语义抽取器能够识别以下 `observed_features`：

```text
更换新猫粮
大便偏软
精神良好 / 精神正常
食欲正常
饮水正常
呕吐 denied
血便 denied
```

但问诊语义抽取器仍返回空集合。

该现象说明两个语义 Agent 对同一原文的事实覆盖结果不一致，而当前链路没有显式的一致性检查、冲突标记或覆盖率告警。

#### 影响

1. 相同用户事实在不同领域出现不同结构化结果。
2. 状态层无法判断空结果是“用户未提供”还是“问诊语义漏抽”。
3. 后续排查需要依赖人工比对多个 metadata。
4. 真实模型输出漂移缺少可观测信号。

### 2.5 多轮补充后问诊状态无法恢复

#### 问题描述

第二轮用户输入几乎逐项回答第一轮追问，包括：

```text
精神正常
会主动玩
对呼唤有反应
进食量和平常一样
饮水频率和总量没变
没有呕吐
没有干呕
没有反流
没有流涎
没有舔唇
大便偏软但没有血
一天一次
前天开始换新猫粮
```

但第二轮问诊语义仍返回空集合，问诊状态槽位未更新，仅 `followup_rounds` 与已问问题数量发生变化。

#### 影响

1. 多轮状态存储本身未丢失，但每轮新增事实无法进入状态。
2. 用户补充信息无法降低未知槽位数量。
3. 系统可能重复询问相同槽位。
4. 问诊漏斗收敛依赖追问轮数上限而非事实完成度。

### 2.6 相似低风险输入的临床安全语义分类不稳定

#### 问题描述

A/B 与 C/D 的医学内容高度相似，均为低风险软便、换粮、精神食欲正常、无呕吐和无血便场景，但临床安全语义输出出现分歧：

| 复测 | `risk_evidence_state` | 临床召回 | 前提评估 |
|---|---|---|---|
| A | `insufficient` | `stage=none` | 未进入前提评估 |
| B | `insufficient` | `stage=none` | 未进入前提评估 |
| C | `sufficient` | `vector`, `candidate_count=12` | `required_count=9`, `unknown_count=9` |
| D | `sufficient` | `vector`, `candidate_count=12` | `required_count=9`, `unknown_count=9` |

C/D 中前提评估还出现：

```text
clinical_safety_precondition_invalid_evidence
clinical_safety_precondition_total_timeout
```

#### 影响

1. 相似输入进入不同临床安全路径。
2. 低风险普通问诊可能被带入大量急诊候选前提评估。
3. `clinical_safety_precondition_unknown` 会进一步阻塞普通问诊阶段性回答。
4. 请求耗时升高至数十秒。
5. 安全上没有产生 urgent signal，但体验上表现为过度追问。

### 2.7 normal 与 denied 的语义表示存在歧义

#### 问题描述

部分临床安全输出中出现：

```text
denied: 精神正常
denied: 食欲正常
denied: 饮水正常
```

该表示无法清晰区分：

1. 用户明确报告“精神状态正常”。
2. 用户明确否认“精神异常”。
3. 系统缺少精神状态信息。

#### 影响

1. 正常状态、否定异常和未知状态可能被混淆。
2. 后续策略难以可靠消费。
3. 审计解释存在歧义。

## 3. 当前期望行为

以下为业务验收口径，不规定实现方式。

### 3.1 原始低风险软便场景

对包含以下信息的输入：

```text
前天开始换新猫粮
大便软
无血便
精神正常
食欲正常
饮水正常
无呕吐
```

系统应能够将这些显式信息进入问诊状态，不应把已明确报告的正常状态或否定状态继续判定为未知。

### 3.2 否定事实

用户明确否认呕吐、血便、干呕等症状时，应作为否定证据进入问诊状态，并用于减少对应槽位的追问需求。

### 3.3 answer-now 意图

用户明确表达“先根据现有信息回答”“不要继续追问”“直接给阶段建议”时，应被识别为 `answer_now` 意图。

在不存在当前 urgent / blocked 安全信号时，系统应尊重该意图并给阶段性回答；存在安全风险时，应按安全策略优先处理并给出可解释原因。

### 3.4 多轮收敛

用户第二轮逐项回答已问问题后：

1. 新增事实应进入问诊状态。
2. 不应重复询问已回答槽位。
3. 除仍有医学必要的信息缺口外，应进入阶段回答。

### 3.5 跨 Agent 一致性

同一用户原文中的显式事实在不同语义 Agent 间不应出现一边识别、一边完全为空且无告警的状态。若出现不一致，系统应有可观察的冲突或覆盖率信号。

### 3.6 低风险输入稳定性

语义高度相似的低风险换粮软便请求不应在 `risk_evidence_state`、临床召回和前提评估路径上发生不可解释的漂移。

### 3.7 临床安全回归底线

修复不得造成以下回退：

1. 模糊分诊直接升级急诊。
2. 明确否认呕吐或血便被当作 present 症状。
3. 无高风险证据时触发 urgent / blocked 安全信号。
4. OPA 或 Python 重新扫描原始用户文本做医学判断。

## 4. 影响范围

### 4.1 受影响链路

```text
用户输入
→ 问诊语义抽取
→ 问诊状态合并
→ 回答充分性 OPA 裁决
→ followup RAG
→ 用户追问输出
```

同时关联：

```text
临床安全语义抽取
→ 临床安全召回准入
→ required_context 前提评估
→ clinical_safety_precondition_unknown 与普通问诊回答准入的联动
```

### 4.2 受影响能力

1. 单轮低风险问诊回答。
2. 多轮问诊状态收敛。
3. answer-now 用户控制意图。
4. 否定与正常状态消费。
5. 追问质量。
6. 临床安全低风险分类稳定性。
7. 请求延迟。
8. 语义可观测性与排障能力。

### 4.3 风险等级

P1。

该问题当前未观察到误升级急诊或遗漏 urgent 安全信号，但会显著影响问诊闭环、用户体验和多轮收敛能力，并造成数十秒级响应延迟。

## 5. 修复边界

### 5.1 纳入范围

1. 问诊语义抽取对显式事实的覆盖能力。
2. 正常状态的抽取与状态消费。
3. 否定状态的抽取与状态消费。
4. 起病时间、当前食物、换粮、大便形态等显式槽位。
5. `answer_now` 控制意图识别。
6. 空结果的可疑性识别与可观测性。
7. 问诊语义与临床安全语义的一致性检查。
8. 多轮补充后的状态收敛。
9. 低风险软便 / 换粮输入的临床安全分类稳定性。
10. `clinical_safety_precondition_unknown` 对普通问诊回答准入的影响。
11. 真实模型回归样本与预发布观察指标。

### 5.2 不纳入范围

1. 不修改临床安全资产的医学准入内容。
2. 不按疾病名、症状词或资产 code 在 Python 中编写医学分支。
3. 不恢复硬关键词规则状态机。
4. 不让 OPA 扫描原始用户文本。
5. 不将 `clinical_safety_semantic.observed_features` 未经契约转换直接写入问诊状态。
6. 不简单放宽回答充分性策略来掩盖上游漏抽。
7. 不把 `required_context` unknown 静默改成 not satisfied。
8. 不通过本地默认追问模板掩盖语义抽取失败。
9. 不处理 Guardrails 输出增强或 rewrite 实现。
10. 不处理阶段 5 预发布部署、网络和镜像发布问题。

### 5.3 必须保持的架构边界

1. 问诊语义抽取、临床安全语义抽取、状态合并和策略裁决职责应保持分离。
2. Python 编排层不得重新实现医学规则状态机。
3. OPA 继续消费结构化输入，不接收完整原始用户文本。
4. 临床安全与普通问诊之间如需共享事实，必须通过明确定义的结构化契约，不允许隐式字段复制。
5. 模型失败、结构化失败和覆盖率不足应有显式状态，不得静默降级。

## 6. 验收基线

### 6.1 A：原始输入复测

输入：

```text
我家英短前天开始换新猫粮，这两天大便有一点软，但精神挺好，饭和水都正常，没有呕吐，也没有血便。我要不要先把粮换回去？
```

验收要求：

1. HTTP 200。
2. 不产生 urgent / blocked 安全信号。
3. 问诊语义结果不得在存在上述显式事实时返回不可审计的空集合。
4. 问诊状态应消费起病时间、当前食物、大便形态、精神状态、食欲饮水和呕吐否定。
5. 系统不应重复询问精神状态、食欲饮水或呕吐。

### 6.2 B：规范化表达复测

规范化输入仍应满足 A 的验收要求，证明问题不由口语表达歧义导致。

### 6.3 C：answer-now 控制组

输入明确包含：

```text
请先根据现有信息给阶段建议，不要继续追问
```

验收要求：

1. `intent.answer_now=true`。
2. 无 urgent / blocked 安全信号时，最终状态应为 `completed`。
3. 响应应是基于现有信息的阶段性回答。
4. 不得继续输出与已有信息冲突的追问。

### 6.4 D：第二轮逐项补充

第二轮输入覆盖第一轮追问的各槽位。

验收要求：

1. 新增事实进入问诊状态。
2. 不重复询问已回答槽位。
3. 除医学必要缺口外，应进入阶段回答。
4. `followup_rounds` 不应成为唯一收敛手段。

### 6.5 临床安全一致性

A/B/C/D 均不得产生：

```text
urgent signal
blocked signal
```

相似低风险输入的临床安全路径应可解释且稳定。

### 6.6 审计与回归

1. 语义空结果、覆盖率不足或跨 Agent 不一致应有可观察 metadata。
2. 至少覆盖 A/B/C/D 四类真实模型回归样本。
3. 回归样本应包含正常状态、否定状态、时间、换粮、大便形态、控制意图和多轮补充。
4. 预发布观察应记录空抽取率、重复追问率、answer-now 识别率、required_context unknown 率和请求耗时。
