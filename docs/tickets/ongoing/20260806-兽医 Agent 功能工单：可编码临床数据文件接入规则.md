# 兽医 Agent 功能工单：可编码临床数据文件接入规则

## 1. 工单背景

兽医 Agent 需要使用结构化临床数据作为安全识别、问诊追问、诊断证据展示和阶段性回答生成的基础输入。当前交付包中，可编码数据位于 `tmp/feature/data`，包含安全参考数据与常见病症数据。

本工单用于归档可编码数据文件的功能需求、数据边界、临床安全约束与验收要求。

## 2. 数据资产范围

### 2.1 安全参考数据

文件：`tmp/feature/data/vet_safety_reference.json`

该数据用于支持安全层相关能力，包含：

- 毒物与人药风险数据。
- 急症红旗症状数据。
- 隐匿高风险语义模式数据。
- 用户常见表达、别名、物种差异、紧急度、处置边界和来源信息。

### 2.2 常见病症数据

文件：`docs/tickets/assets/vet_safety_reference.json`

该数据用于支持临床知识增强能力，包含：

- 常见犬猫病症卡。
- 典型表现。
- 鉴别方向。
- 病症特异追问。
- 分诊建议。
- 升级红旗。
- 用药方向。
- 居家护理。
- 来源信息。

## 3. 功能需求

### 3.1 系统需支持结构化临床数据资产

系统需能够将 `tmp/feature/data` 下的结构化 JSON 数据作为可编码临床知识资产识别和管理。

该能力应覆盖安全参考数据与常见病症数据，并保证数据内容在进入生产使用前具备明确的来源、版本、审核状态和可追溯信息。

### 3.2 安全参考数据需进入安全能力边界

系统需具备使用安全参考数据识别以下风险的能力：

- 毒物摄入风险。
- 人用药误用风险。
- 急症红旗症状。
- 物种特异高危场景。
- 隐匿高风险语义模式。
- 用户表达中的别名、商品名、俗称和间接描述。

安全参考数据中的高风险内容不得仅作为普通知识问答素材使用。

### 3.3 常见病症数据需进入问诊与回答能力边界

系统需具备使用常见病症数据增强以下能力：

- 根据用户主诉召回相关病症知识。
- 根据病症特异追问生成更有区分度的问题。
- 根据典型表现和鉴别方向形成阶段性判断依据。
- 根据分诊建议和升级红旗输出安全边界。
- 根据居家护理字段提供非处方、非剂量化的护理建议。
- 在 `reasoning_display` 中展示用户可见的诊断证据来源。

### 3.4 别名与用户表达需区分用途

数据中的 `aliases`、用户描述样例、俗称和常见表达属于临床识别辅助信息。

这些内容可用于语义理解、召回增强和用户表达归一，但不得未经审核直接等同于确定性急症判断条件。

### 3.5 用药内容需遵守统一口径

系统涉及用药相关内容时，需满足以下业务约束：

- 可展示正规兽药的药名或成分方向。
- 不得给出具体剂量。
- 处方药必须提示遵从兽医。
- 人用药、禁忌药、毒物摄入场景必须进入安全警示或升级路径。
- 用药方向不得被包装为确诊后治疗方案。

### 3.6 临床资料不得等同于临床验证

结构化数据属于权威资料汇编，不等同于临床诊断验证。

凡涉及以下内容，均需具备临床审核要求：

- 急症分级。
- 毒物和人药风险。
- 物种特异禁忌。
- 用药方向。
- 分诊边界。
- 居家护理边界。
- 面向用户的医疗建议表述。

## 4. 问题范围

当前系统若缺少该数据资产规则，可能出现以下问题：

- 临床内容散落在文档或代码中，难以审计。
- 安全层只能覆盖显性关键词，隐匿高风险场景识别不足。
- 问诊追问容易退化为通用模板。
- 不同病症的追问缺少临床区分度。
- 用药相关内容可能缺少统一边界。
- 后台无法稳定追踪数据来源、版本和审核状态。
- 生产环境无法清晰判断当前使用的是哪一版临床知识。

## 5. 验收要求

| 编号 | 验收项 | 预期结果 |
|---|---|---|
| A1 | 安全参考数据可被系统识别 | 毒物、人药、急症红旗和危险语义模式具备可追溯来源 |
| A2 | 常见病症数据可被系统识别 | 105 条病症卡可作为临床知识资产进入系统能力边界 |
| A3 | 病症特异追问可被使用 | 追问不再只依赖通用“精神、食欲、是否萎靡”模板 |
| A4 | 用药口径受控 | 输出不得包含具体剂量，不得建议用户自行使用人药 |
| A5 | 诊断证据可展示 | 用户可见证据中能体现用户回答、宠物资料和临床知识来源 |
| A6 | 临床审核可追溯 | 生产使用的数据需能追踪来源、版本和审核状态 |
| A7 | 临时资料不进入生产资产 | 临时目录内容不得作为正式提交或生产依赖 |

## 6. 风险等级

| 风险项 | 等级 | 说明 |
|---|---|---|
| 安全参考数据未接入 | P0 | 可能导致毒物、人药、急症红旗和隐匿高风险场景漏判 |
| 病症卡未结构化使用 | P1 | 可能导致追问模板化、回答依据不足 |
| 用药口径未统一 | P0 | 可能产生具体剂量、人药误用或危险建议 |
| 数据无审核追踪 | P1 | 影响生产审计、问题回滚和临床责任边界 |
| 临时目录误提交 | P2 | 增加仓库噪音和生产依赖不确定性 |

## 7. 非目标范围

本工单不覆盖以下内容：

- 具体数据库表结构设计。
- 具体 API 设计。
- 具体 RAG 切分策略。
- 具体代码实现路径。
- 具体提示词实现。
- 具体部署命令。
